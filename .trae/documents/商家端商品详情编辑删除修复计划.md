# 商家端商品详情编辑删除修复计划

## Summary

目标：修复商家端“商品管理”中商品可列表展示，但无法查看详情、无法进入编辑、无法删除的问题，并确保从“商家登录 → 登录态携带 merchant_id → 商品列表查询 → 商品详情/编辑/删除”整条链路的数据关联一致。

本次修复以“最小改动恢复功能”为原则，不改动无关业务流程，优先修正接口数据结构、模型关联、删除语义和前端页面加载顺序。

## Current State Analysis

### 1. 登录态与商家归属链路当前是通的

已确认实际链路如下：

1. `miniprogram/src/pages/auth/login.vue`
   - 商家端使用账号密码登录，调用 `authStore.login()`。
2. `miniprogram/src/stores/auth.ts`
   - 调用 `merchantLogin()`，保存 `token` 与 `merchantId`。
3. `miniprogram/src/api/index.ts`
   - `merchantLogin()` 请求 `/api/v1/auth/merchant/login`。
4. `server/internal/handlers/merchant/handler.go`
   - `Login()` 使用 `staff.MerchantID` 生成 JWT，并返回 `merchant_id`。
5. `server/internal/middleware/auth.go`
   - `GetMerchantID()` 直接取 JWT 中的 `user_id`，当前即商家 ID。
6. `server/internal/handlers/merchant/product.go`
   - `GetProducts()` / `GetProduct()` / `DeleteProduct()` 都使用 `merchant_id` 作为归属过滤条件。

结论：商品列表能查出来，说明“登录态 -> JWT -> merchant_id -> 列表查询”的商家归属链路本身是成立的，问题主要不在登录态，而在商品详情/编辑/删除对应的接口和数据结构。

### 2. 商品列表的数据来源已确认

商品列表页面的真实数据来源如下：

1. `miniprogram/src/pages/merchant/products/list.vue`
   - `onShow()` 中调用 `loadProducts(true)`。
   - `loadProducts()` 调用 `getProducts(params)`。
2. `miniprogram/src/api/index.ts`
   - `getProducts()` 请求 `GET /api/v1/merchant/products`。
3. `server/internal/handlers/merchant/product.go`
   - `GetProducts()` 按 `merchant_id`、`category_id`、`status`、`keyword` 查询 `products` 表。

结论：列表页是以后端 `products` 表为准，不是前端本地拼装数据；后续详情/编辑/删除必须以同样的 `merchant_id + product_id` 关系继续走通。

### 3. 商品详情/编辑失败的核心断点

#### 3.1 后端预加载了不存在的 `Specs` 关联

已确认：

- `server/internal/handlers/merchant/product.go`
  - `GetProduct()` 使用 `Preload("Category").Preload("Specs")`
  - `CreateProduct()` 保存后使用 `Preload("Category").Preload("Specs")`
  - `UpdateProduct()` 保存后使用 `Preload("Category").Preload("Specs")`
- `server/internal/models/models.go`
  - `models.Product` 中只有 `Merchant`、`Category`，没有 `Specs []ProductSpec` 字段

这会导致详情接口及编辑页回填依赖的商品详情查询在运行时出现关系加载错误，从而直接解释“列表能打开，但详情/编辑不行”。

#### 3.2 商品 JSON 字段未被转换为前端可直接使用的结构

已确认：

- `models.Product.Images` 类型是自定义 `JSON`
- `models.ProductSpec.Options` 类型也是自定义 `JSON`
- 当前商家端接口直接把 Gorm 模型返回给前端
- 前端 `miniprogram/src/pages/merchant/products/edit.vue` 期望：
  - `product.images` 是 `string[]`
  - `product.specs` 是 `{ name, options[] }[]`

如果后端直接返回模型，`images/options` 很可能不是页面期望的结构，编辑页回填会异常，即使接口不报错，页面也可能空白、规格回显失败或图片列表无法操作。

#### 3.3 编辑页的分类回显还有加载时序问题

已确认：

- `miniprogram/src/pages/merchant/products/edit.vue`
  - `onLoad()` 里先调 `loadCategories()`，同时立刻根据 `options.id` 调 `loadProduct()`
  - `loadProduct()` 中会立即执行 `findIndex(c => c.id === product.category_id)`
- 但此时 `categories` 可能还没加载完，导致分类索引回显失败

这不是详情加载失败的唯一原因，但会造成“进入编辑页后分类不显示/显示异常”。

### 4. 删除失败的核心断点

#### 4.1 当前实现是硬删除，与 PRD 不一致

已确认：

- `PRD.md` 中定义：`商品删除 | 删除商品（软删除）`
- `server/internal/handlers/merchant/product.go`
  - `DeleteProduct()` 当前直接执行 `DELETE FROM products`

这与 PRD 的“软删除”设计不一致。

#### 4.2 数据库外键会拦截已有关联订单的商品硬删除

已确认：

- `server/migrations/20240101000000_full_init.sql`
  - `order_items.product_id -> products.id` 为 `ON DELETE RESTRICT`

这意味着只要该商品参与过历史订单，当前硬删除就会被数据库拒绝，导致商家端“删除失败”。

#### 4.3 当前查询未排除软删除数据

已确认：

- `models.Product` 已有 `DeletedAt *time.Time`
- 但 `GetProducts()`、`GetProduct()` 等查询没有统一过滤 `deleted_at IS NULL`

即便改成软删除，如果不补齐查询过滤，列表和详情仍可能出现已删除商品。

## Proposed Changes

### 1. 修复后端商品模型关联与返回结构

#### 文件：`server/internal/models/models.go`

变更内容：

- 为 `models.Product` 增加 `Specs []ProductSpec` 关联字段，声明 `gorm:"foreignKey:ProductID"`。

原因：

- 让 `Preload("Specs")` 成为合法关系，恢复商品详情、创建后返回、更新后返回的关联加载能力。

实施方式：

- 在 `Product` 结构体中新增 `Specs` 字段，不改动已有字段名和表结构映射。

### 2. 为商家商品接口增加统一 DTO 转换

#### 文件：`server/internal/handlers/merchant/product.go`

变更内容：

- 新增商品响应转换辅助方法，例如：
  - 将 `product.Images` 从 JSON 转成 `[]string`
  - 将 `product.Specs[].Options` 从 JSON 转成前端期望的数组对象
  - 补充 `category_name`
- `GetProducts()` 改为返回转换后的列表数据
- `GetProduct()` 改为返回转换后的详情数据
- `CreateProduct()` / `UpdateProduct()` 在保存成功后，也返回转换后的标准商品结构

原因：

- 前端页面和类型定义都按“结构化对象”使用 `images/specs/options`，接口需要返回稳定、可直接消费的数据，而不是数据库原始 JSON 字段。

实施方式：

- 在 `product.go` 内新增局部响应结构和转换函数，避免影响其他模块。
- 只在商家商品接口中落地，不扩大改动范围。

### 3. 修复商家商品编辑页的数据回填时序

#### 文件：`miniprogram/src/pages/merchant/products/edit.vue`

变更内容：

- 调整 `onLoad()` 的加载顺序：
  - 先加载分类
  - 再根据 `id` 加载商品详情
- 或者在分类加载完成后，根据 `formData.category_id` 补算 `categoryIndex`
- 对详情加载失败补充明确的页面提示和回退处理

原因：

- 避免“详情已拿到，但分类数组尚未加载完成”导致分类选择器无法正确回显。

实施方式：

- 使用 `async` 顺序调用或在 `loadCategories()` 结束后统一执行分类索引同步。
- 不改动表单字段结构，只修正加载时机和错误反馈。

### 4. 将商品删除改为软删除，并与历史订单兼容

#### 文件：`server/internal/handlers/merchant/product.go`

变更内容：

- `DeleteProduct()` 改为更新 `deleted_at`（当前时间）而不是物理删除。
- 同时建议把商品状态置为下架，避免删除后仍被当作可售商品使用。
- 删除前仍按 `id + merchant_id + deleted_at IS NULL` 校验归属和有效性。

原因：

- 与 PRD 一致。
- 避免被 `order_items` 外键拦截。
- 保留历史订单引用，保证订单快照完整性。

实施方式：

- 仅更新 `products` 表，不物理删除 `product_specs`。
- 让已删除商品不再出现在商家商品列表和详情中。

### 5. 给所有商家商品查询补齐“未删除”过滤

#### 文件：`server/internal/handlers/merchant/product.go`

变更内容：

- `GetProducts()` 查询增加 `deleted_at IS NULL`
- `GetProduct()` 查询增加 `deleted_at IS NULL`
- `UpdateProduct()` 查询增加 `deleted_at IS NULL`
- `ProductOnSale()` / `ProductOffSale()` / `BatchUpdateProductStatus()` / `UpdateStock()` 也增加 `deleted_at IS NULL`

原因：

- 软删除后，所有商品管理操作必须统一忽略已删除商品，避免脏数据重新被操作。

实施方式：

- 在现有 `Where("id = ? AND merchant_id = ?", ...)` 基础上补充 `deleted_at IS NULL` 条件。

### 6. 让商家商品列表页删除后的前端表现与后端语义一致

#### 文件：`miniprogram/src/pages/merchant/products/list.vue`

变更内容：

- 保留现有删除交互，但删除成功后继续从当前列表中移除该商品。
- 若后端返回“商品不存在/已删除”，前端提示后刷新列表。
- 若详情按钮与编辑按钮都进入同一页面，则保留当前路径，不额外新增详情页，优先恢复现有流程可用性。

原因：

- 用户当前的核心诉求是“能看详情、能编辑、能删除”，不是新增独立详情页。
- 在不扩大页面改造的前提下，先恢复点击链路。

实施方式：

- 最小范围调整错误处理与删除后的数据刷新逻辑。

### 7. 视情况补一层前端容错归一化

#### 文件：`miniprogram/src/api/index.ts`

变更内容：

- 如后端响应仍可能出现 `images/specs/options` 非数组的历史数据，新增轻量 `normalizeProduct()` / `normalizeProductList()` 容错处理。

原因：

- 即便后端修正后，数据库历史数据或旧接口缓存仍可能造成短期异常；在 API 层做一次兜底，能降低页面崩溃风险。

实施方式：

- 仅对商家商品相关接口应用，不影响其他 API。

说明：

- 这是兜底层，不替代后端主修复。
- 如果实现阶段确认后端 DTO 已完全稳定，可将这一项降为非必选。

## Assumptions & Decisions

### 已锁定决策

1. 删除语义按 PRD 执行，采用软删除，不再继续使用硬删除。
2. 不新增独立“商品详情页”，沿用当前“点击列表进入编辑页”的现有交互，只修复其无法加载详情数据的问题。
3. 商品归属以登录后 JWT 中的 `merchant_id` 为唯一依据，不改动认证方式。
4. 优先在后端统一返回正确商品结构，前端只做轻量兜底，不把主要数据转换逻辑堆到页面内。

### 实施假设

1. 当前报错的主因包括：
   - `Preload("Specs")` 关系不存在
   - 商品 JSON 字段未转前端结构
   - 删除仍是硬删除
2. 列表接口之所以“能出来”，是因为它只依赖 `products` 基础字段，没有进入详情所需的 `Specs` 关系和表单回填链路。

## Verification Steps

执行修复后，按以下顺序验证：

1. 商家登录验证
   - 使用商家账号登录
   - 确认可正常进入 `pages/merchant/home`

2. 商品列表验证
   - 进入 `pages/merchant/products/list`
   - 确认商品列表能正常显示
   - 分类筛选、状态筛选、搜索后列表仍正常返回

3. 商品详情/编辑验证
   - 点击任一商品图片或商品内容区域
   - 确认进入 `pages/merchant/products/edit?id=xxx`
   - 确认名称、分类、描述、价格、库存、图片、规格都能正确回填
   - 修改后保存，返回列表并再次进入，确认数据已更新

4. 商品删除验证
   - 删除一个未关联订单的商品，确认前端提示成功且列表消失
   - 删除一个已有关联订单的商品，确认也能成功（软删除）
   - 删除后刷新列表，确认该商品不再出现
   - 直接访问已删除商品详情，确认返回“商品不存在”或等价提示

5. 边界验证
   - 已删除商品不能再被上架/下架/改库存
   - 批量上下架不会误操作已删除商品
   - 编辑页在分类先慢后快的情况下仍能正确回显分类

6. 回归验证
   - 新建商品后立即进入编辑页，确认不会因 `Specs` 关系加载报错
   - 商家商品列表分页与删除后刷新逻辑保持可用
