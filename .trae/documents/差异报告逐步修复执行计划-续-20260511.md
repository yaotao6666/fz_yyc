# 差异报告逐步修复执行计划（续）

## 摘要

当前阻塞点是 **小程序 mp-weixin 构建失败**：`pages/sp/**` 引用的 `@types` 与 `@api` 符号缺失，且部分 SP 页面期望的后端返回结构与现有 SP 接口不一致。此计划以“不轻易改动既有逻辑”为原则，优先补齐 **SP 前端 types/API 导出** 并对后端 **SP 接口的缺口** 做最小补齐，使构建通过并可完成 SP 关键链路的基础联调。

## 现状分析（基于仓库实况）

### 1) 前端构建阻塞：缺失导出

SP 页面中缺失的符号已确认如下（均为编译期 hard error）：

- `@types` 缺失：`MerchantListItem`、`SpSettings`、`MerchantApplication`、`MerchantAuditStatus`、`MerchantAuditStatusText`、`MerchantDetail`、`AnnouncementStatus`、`MerchantDistributionData`、`OrderAnalyticsData`、`AmountAnalyticsData`、`TopMerchantRanking`
- `@api` 缺失：`getMerchantList`、`getMerchantDetail`、`getSpSettings`、`changeSpPassword`、`spLogout`、`getSpMerchantsPending`、`getAnnouncements`、`getAnnouncement`、`createAnnouncement`、`updateAnnouncement`、`getMerchantDistribution`、`getOrderAnalytics`、`getAmountAnalytics`、`getTopMerchants`

- types 入口：[miniprogram/src/types/index.ts](file:///e:/other/fz_yyc/miniprogram/src/types/index.ts)

### 2) 后端 SP 接口与页面期望不一致（会导致运行期异常）

从页面对真实调用点反推，以下接口必须满足页面的字段/结构期望：

- 商家审核列表页 [audit.vue](file:///e:/other/fz_yyc/miniprogram/src/pages/sp/merchants/audit.vue)：
  - 期望 `getSpMerchantsPending(params)` 支持 `status/keyword/page/page_size`，并返回 `list` 中对象包含 `name/contact_name/contact_phone/business_category/applied_at/status/reject_reason` 等字段。
  - 现有后端 `sp.GetPendingMerchants` 仅固定查 `audit_status=0`，且返回的是 `models.Merchant`（字段名与页面使用的 `applied_at/reject_reason/status` 等不一致）。
- 审核详情页 [audit-detail.vue](file:///e:/other/fz_yyc/miniprogram/src/pages/sp/merchants/audit-detail.vue)：
  - 直接 GET `/api/v1/sp/merchants/:id`，并期望响应包含 `application.business_license_info/legal_person_info/bank_account_info/store_info`。
  - 现有后端 `sp.GetMerchantDetail` 仅返回 `models.Merchant`，不含 `application`。
- 服务商设置页 [settings.vue](file:///e:/other/fz_yyc/miniprogram/src/pages/sp/settings.vue)：
  - 期望 `getSpSettings()` 返回 `admin_name/contact_phone/...`，并提供 `changeSpPassword({old_password,new_password})`。
  - 现有后端仅有 `GET/PUT /api/v1/sp/settings`（且实现为 `database.DB.First(&sp)`，未绑定当前登录管理员），无改密接口。
- 服务商公告编辑页 [edit.vue](file:///e:/other/fz_yyc/miniprogram/src/pages/sp/announcements/edit.vue)：
  - 期望 `getAnnouncement(id)`、`createAnnouncement(data)`、`updateAnnouncement(id,data)`，且 data 携带 `status`（草稿/发布）。
  - 现有后端路由无 `GET /api/v1/sp/announcements/:id`，且 Create/Update request 未接受 `status`（虽不影响 binding，但草稿逻辑不会生效）。

后端路由清单（SP 部分）：[server/cmd/server/main.go](file:///e:/other/fz_yyc/server/cmd/server/main.go#L216-L262)

## 目标与验收标准

### 目标

1) 小程序 `build:mp-weixin` 通过（不再因 SP 页面 types/api 缺失而失败）。
2) SP 关键链路可基础联调（至少无明显 404/字段缺失导致的页面崩溃）：
   - 登录 → 首页 → 审核列表 → 审核详情 → 通过/拒绝
   - 商家列表 → 商家详情
   - 公告列表 → 新建/编辑公告
   - 设置页：读取设置、改密、退出登录
3) 后端 `go test ./...` 通过。

### 验收标准

- 前端：`npm run build:mp-weixin` 成功完成，且运行时进入 SP 页面不出现“接口 404 / undefined 读取属性”这类阻断问题（以控制台报错为准）。
- 后端：新增/调整的 SP API 返回结构与页面使用字段对齐，且统一响应结构仍为 `response.Success/Fail`。

## 方案与改动点（按“先解阻塞，再补对接”排序）

### Step 1：补齐前端 types（仅新增，不破坏现有类型）

文件： [miniprogram/src/types/index.ts](file:///e:/other/fz_yyc/miniprogram/src/types/index.ts)

新增导出（按现有风格集中在一个文件里，snake_case 字段名保持与后端一致）：

- `export enum MerchantAuditStatus { PENDING = 0, APPROVED = 1, REJECTED = 2 }`
- `export const MerchantAuditStatusText: Record<number, string>`（映射 0/1/2）
- `export interface MerchantApplication`（用于审核列表页展示的扁平字段，包含 `applied_at/reject_reason/status` 等）
- `export interface MerchantListItem`（用于商家列表页：包含 `created_at`、并确保 `total_amount/total_orders/total_users` 可为 0）
- `export interface MerchantDetail`（用于商家详情页：包含 `license/settings/store_name/qrcode_url/total_*` 等页面用到字段）
- `export interface SpSettings`（对齐设置页展示字段，如 `name/admin_name/contact_phone/contact_email/created_at`）
- `export type AnnouncementStatus = 0 | 1`（与页面草稿/发布一致）
- 统计相关：
  - `export interface MerchantDistributionData`（对齐后端 `sp.GetMerchantDistribution` 返回的 `business/status` 两组）
  - `export interface OrderAnalyticsData`（对齐后端 `sp.GetOrderAnalytics`）
  - `export interface AmountAnalyticsData`（对齐后端 `sp.GetAmountAnalytics`）
  - `export interface TopMerchantRanking`（对齐后端 `sp.GetTopMerchants` 返回数组项）

决策：types 不做“全局重构/统一字段风格”，仅新增 SP 所需类型，避免对既有页面产生连锁影响。

建议 types 关键字段（仅列页面确实使用到的字段，避免过度设计）：

- `MerchantApplication`
  - `id: number`
  - `name: string`
  - `contact_name: string`
  - `contact_phone: string`
  - `business_category: string`
  - `applied_at: string`
  - `status: number`
  - `reject_reason?: string`
- `MerchantListItem`
  - `id/name/business_category/status/created_at`
  - `total_users: number`
  - `total_orders: number`
  - `total_amount: number`
- `MerchantDetail`
  - 复用 `MerchantListItem` 的字段，并补充：
  - `address?: string`
  - `audit_status: number`
  - `audit_remark?: string`
  - `qrcode_url?: string`
  - `store_name?: string`
  - `license?: any`
  - `settings?: { bank_account?: any; store_images?: string[] }`
  - `application?: { business_license_info?: any; legal_person_info?: any; bank_account_info?: any; store_info?: any }`
- `SpSettings`
  - `name: string`
  - `admin_name: string`
  - `contact_phone: string`
  - `contact_email?: string`
  - `created_at?: string`

### Step 2：补齐前端 SP API 封装与导出（薄封装 + 必要兜底）

文件： [miniprogram/src/api/index.ts](file:///e:/other/fz_yyc/miniprogram/src/api/index.ts)

新增导出函数（保持与现有 `get/post/put/del` 封装一致，路径统一 `/api/v1/sp/` 以自动携带 `sp_token`）：

- 审核/商家：
  - `getSpMerchantsPending(params)` → `GET /api/v1/sp/merchants/pending`
  - `getMerchantList(params)` → `GET /api/v1/sp/merchants/list`
  - `getMerchantDetail(id)` → `GET /api/v1/sp/merchants/:id`
- 统计：
  - `getMerchantDistribution()` → `GET /api/v1/sp/merchants/analytics/distribution`
  - `getOrderAnalytics(params?)` → `GET /api/v1/sp/orders/analytics`
  - `getAmountAnalytics(params?)` → `GET /api/v1/sp/amount/analytics`
  - `getTopMerchants(params?)` → `GET /api/v1/sp/amount/top-merchants`
- 设置/鉴权：
  - `getSpSettings()` → `GET /api/v1/sp/settings`
  - `changeSpPassword(body)` → `POST /api/v1/sp/account/change-password`（新增后端路由，见 Step 3）
  - `spLogout()` → `POST /api/v1/sp/auth/logout`
- 公告：
  - `getAnnouncements(params)` → `GET /api/v1/sp/announcements`
  - `getAnnouncement(id)` → `GET /api/v1/sp/announcements/:id`（新增后端路由，见 Step 3）
  - `createAnnouncement(body)` → `POST /api/v1/sp/announcements`
  - `updateAnnouncement(id, body)` → `PUT /api/v1/sp/announcements/:id`

必要兜底（避免页面因后端暂未补齐统计字段而崩溃）：
- `getMerchantList` 返回的每个 item 若缺 `total_amount/total_orders/total_users`，在 API 层补 0，保证 [list.vue](file:///e:/other/fz_yyc/miniprogram/src/pages/sp/merchants/list.vue) 的 `formatAmount(merchant.total_amount)` 不会收到 `undefined`。
- `getAnnouncements` 如缺少 `summary/published_at`，在前端按 `content` 截断生成 `summary`，并用 `created_at` 补 `published_at`（不改后端表结构）。

### Step 3：补齐/对齐后端 SP 侧缺口（最小可用）

#### 3.2 服务商改密

文件： [server/internal/handlers/sp/handler.go](file:///e:/other/fz_yyc/server/internal/handlers/sp/handler.go)

新增 handler：`ChangePassword(c *gin.Context)`：
- 从 JWT 上下文获取当前管理员 ID（依赖现有 JWTAuth 行为）。
- 校验 `old_password/new_password`，使用 bcrypt 比对与生成 hash。
- 更新 `service_provider_admins.password`。
- 返回 `{"message":"修改成功"}`。

#### 3.3 服务商设置读取对齐（绑定当前登录管理员）

文件： [server/internal/handlers/sp/handler.go](file:///e:/other/fz_yyc/server/internal/handlers/sp/handler.go)

调整 `GetSettings(c)` 的实现策略：
- 用当前登录的 `ServiceProviderAdmin`（按 token user_id）读取，并 `Preload("ServiceProvider")`。
- 返回结构补齐设置页展示字段：
  - `name`：来自 `ServiceProvider.Name`
  - `admin_name`：优先 `ServiceProviderAdmin.Name`，为空则回退 `ServiceProviderAdmin.Username`
  - `contact_phone`：来自 `ServiceProvider.ContactPhone`
  - `contact_email/created_at`：若后端无对应字段则返回空串/时间（与前端类型保持可选或默认值一致）

决策：不修改 DB 结构，只对响应结构做补齐，以满足页面展示。

#### 3.4 商家审核列表：参数与字段对齐

#### 3.5 商家详情：补齐 application/license/settings 等页面字段

文件： [server/internal/handlers/sp/handler.go](file:///e:/other/fz_yyc/server/internal/handlers/sp/handler.go)

调整 `GetMerchantDetail(c)`：
- 读取 merchant 基本信息。
- 读取该商家的最新 `merchant_applications` 记录（按 `merchant_id` + `created_at desc limit 1`）。
- 组装响应以同时满足：
  - [audit-detail.vue](file:///e:/other/fz_yyc/miniprogram/src/pages/sp/merchants/audit-detail.vue) 需要的 `application.{business_license_info/legal_person_info/bank_account_info/store_info}`
  - [detail.vue](file:///e:/other/fz_yyc/miniprogram/src/pages/sp/merchants/detail.vue) 需要的 `license/settings/store_name/store_images/total_orders/total_amount/qrcode_url`
- 经营数据最小口径：
  - `total_orders`：`orders` 表按 `merchant_id` count
  - `total_amount`：`orders` 表按 `merchant_id` 且 `status >= 2` sum(pay_amount)
  - `total_users`：如缺可暂返回 0（或后续再补）

建议返回结构（示意，均为 `response.Success` 的 data 部分）：

- `GET /api/v1/sp/merchants/:id`
  - 必含（merchant 基础字段）：`id/name/contact_name/contact_phone/address/business_category/status/audit_status/audit_remark/created_at/qrcode_url`
  - application（给审核详情页）：
    - `application.business_license_info`
    - `application.legal_person_info`
    - `application.bank_account_info`
    - `application.store_info`
  - 兼容商家详情页的衍生字段：
    - `license`：直接等于 `application.business_license_info`（字段名对齐页面 `license_no/license_name/legal_person/...`）
    - `settings.bank_account`：等于 `application.bank_account_info`
    - `settings.store_images`：等于 `application.store_info.store_images`（不存在时给空数组）
    - `store_name`：等于 `application.store_info.store_name`（不存在时给空串）
  - 经营数据：
    - `total_orders`（number）
    - `total_amount`（number）
    - `total_users`（number，暂为 0）
