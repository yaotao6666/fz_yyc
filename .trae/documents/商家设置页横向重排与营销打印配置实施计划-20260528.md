# 商家设置页横向重排与营销打印配置实施计划

## 一、Summary

- 目标：
  - 将 `miniprogram/src/pages/merchant/settings.vue` 从纵向列表重构为“顶部信息卡 + 横向功能宫格”布局，提升按钮承载量与扫描效率。
  - 新增商家端“满减营销”配置能力，支持最多 5 档规则、启停状态、C 端下单生效，并在确认订单页展示优惠信息。
  - 新增商家端“打印机管理”页面，复用现有打印机 CRUD，补齐飞鹅打印机参数配置、打印机启停、自动打印、默认打印机与测试打印。
- 范围：
  - 小程序商家端前端页面、前端 API 与类型、C 端确认订单展示、已有后端能力的收口校验、PRD 同步、构建与测试验证。
- 不在范围：
  - 优惠券、发券、复杂营销活动。
  - 打印模板定制、真实打印服务对接改造、音频资源生成。

## 三、Assumptions & Decisions

- 布局决策：
  - `pages/merchant/settings` 采用“顶部信息卡 + 功能宫格”。
  - 宫格优先展示高频入口，每个入口包含图标、标题、简短说明。
- 满减决策：
  - 支持多档满减，最多 5 档。
  - 保存时整体覆盖更新后端规则。
  - 下单优惠以服务端重算为准，前端仅做展示与预估。
  - 规则按“满 X 减 Y”展示，启用状态可单独开关。
- 打印机决策：
  - 继续复用现有打印机 CRUD。
  - 打印机类型至少支持现有通用云打印机与 `feie`。
  - 飞鹅走“通用字段 + 扩展字段”模式：
    - 通用：名称、类型、设备编号、状态、自动打印、默认打印机、打印类型
    - 飞鹅扩展：`feie_user`、`feie_ukey`、`feie_sn`
  - 敏感字段编辑遵循后端脱敏口径：
    - 列表展示不回显密钥明文。
    - 编辑已有打印机时，仅在用户重新输入时覆盖密钥。
- 文档决策：
  - 按现有拆分规则同步更新根 `PRD.md` 与 3 个拆分文档。
  - 文档仅描述“是什么”，不写实现原因。

## 四、Proposed Changes

### 4.1 商家设置页重构

#### `miniprogram/src/pages/merchant/settings.vue`

- 做什么：
  - 重构页面为“商家信息卡 + 功能宫格 + 账号与系统操作区”。
  - 保留现有密码弹窗、微信绑定/解绑、退出登录逻辑。
  - 新增“满减营销”“打印机管理”入口，并继续保留“配送设置”“声音提醒”“员工管理”“分账历史”等入口。
- 为什么：
  - 当前纵向列表信息密度低，新增两个运营模块后将进一步拉长页面，影响效率。
- 怎么做：
  - 顶部卡片展示店铺名称、联系电话、微信绑定状态、下单方式摘要。
  - 中部使用 2 列或 3 列宫格卡片承载功能入口，确保视觉上为横向排版而不是单列堆叠。
  - 员工管理入口继续受 `owner` 角色控制。
  - 入口文案统一短标题 + 副文案，避免只有图标。

### 4.2 满减营销前端

#### `miniprogram/src/pages/merchant/marketing.vue`（新增）

- 做什么：
  - 新增满减营销配置页。
- 为什么：
  - 需要给商家可视化维护多档满减规则。
- 怎么做：
  - 页面提供规则列表编辑能力，每档包含：
    - 满减门槛金额
    - 减免金额
    - 启用状态
  - 支持新增、删除、排序展示、保存。
  - 前端校验与后端口径对齐：
    - 金额必须大于 0
    - 减免金额小于门槛金额
    - 门槛不可重复
    - 最多 5 档
  - 页面显示“当前生效规则预览”，减少误配。

#### `miniprogram/src/api/index.ts`

- 做什么：
  - 新增商家满减规则 API。
- 怎么做：
  - 增加：
    - `getMerchantFullReductionRules()`
    - `updateMerchantFullReductionRules()`
  - 对返回的 `rules` / `active_rules` 做数组兜底和金额归一化。

#### `miniprogram/src/types/index.ts`

- 做什么：
  - 新增满减相关类型。
- 怎么做：
  - 增加：
    - `MerchantFullReductionRule`
    - `MerchantFullReductionRulesResponse`
    - `UpdateMerchantFullReductionRulesRequest`
    - 供 C 端展示使用的公开规则类型

### 4.3 打印机管理前端

#### `miniprogram/src/pages/merchant/printers.vue`（新增）

- 做什么：

- 为什么：
  - 现有后端 CRUD 已具备基础能力，但商家端还没有管理页面。
- 怎么做：
  - 页面分为两块：
    - 打印机列表卡片：展示名称、类型、设备编号、状态、默认状态、自动打印、上次打印时间、累计打印次数。
    - 编辑弹层/表单：新增或编辑打印机。
  - 表单字段：
    - `name`
    - `type`
    - `device_no`
    - `api_key`
    - `api_url`
    - `print_types`
    - `status`
    - `auto_print`
    - `is_default`
    - `feie_user`
    - `feie_ukey`
    - `feie_sn`
  - 类型切换为 `feie` 时，展示飞鹅专属字段并触发必填校验。
  - 编辑已有打印机时，根据后端 `has_api_key` / `has_feie_ukey` 展示“已配置，可重新输入覆盖”的提示。

### 4.4 C 端确认订单页展示满减

#### `miniprogram/src/api/store.ts`

- 做什么：
  - 新增公开满减规则查询接口。
- 怎么做：
  - 增加 `getStoreFullReductionRules(merchantId)`。
  - 对金额字段做统一数值归一化。

#### `miniprogram/src/pages/store/confirm.vue`

- 做什么：
  - 在确认订单页展示可用满减、已命中优惠和实付金额。
- 为什么：
  - 用户要求“配置并下单生效”，前端需要可感知优惠。
- 怎么做：
  - 页面加载时并行获取配送规则与满减规则。
  - 以购物车商品金额为基准，前端预估最优可用规则，仅用于展示。
  - 金额区调整为：
    - 商品金额
    - 配送费
    - 满减优惠（命中时展示负数）
    - 合计/实付
  - 提交订单成功后，以接口返回的 `order.discount_amount`、`order.pay_amount` 为最终口径；必要时用返回值更新支付展示。
  - 当未命中任何规则时，展示“再买 X 元可减 Y 元”的下一档提示。

## 七、Risks

- 前端预估满减与后端最终结算若使用的金额基准不同，可能出现展示差异；执行时必须以服务端返回结果兜底。
- 打印机编辑页若直接清空密钥字段，可能误覆盖已有配置；执行时需要区分“未修改”和“显式重填”。
- `settings.vue` 重构时需保留现有密码弹窗和微信绑定逻辑，不可因样式调整引入行为回归。
