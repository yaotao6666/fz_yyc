# 店铺首页底部加购栏统一计划

## Summary

目标：修复用户端 `pages/store/home` 店铺首页“底部没有加入购物车感知入口”的问题，将店铺首页底部交互统一到和商品详情页相同的设计语言，但不在列表页引入“当前唯一商品立即购买”的复杂选择逻辑。

本次方案已确认的产品决策：

1. 店铺首页不强行复刻商品详情页的“当前商品加入购物车/立即购买”双按钮语义。
2. 店铺首页保留商品卡片内的 `+` 快速加购。
3. 店铺首页底部改为“购物车汇总/去购物车/去结算”风格，视觉与商品详情页底部统一。
4. `我的订单` 不再放在底部 Tab 切换中，改为页面内明显快捷入口。
5. 由于这属于用户端交互变更，需要同步更新 `PRD.md` 中关于店铺首页底部行为的描述。

## Current State Analysis

### 1. 店铺首页当前底部并不是商品详情页那套底栏

当前文件：

- `miniprogram/src/pages/store/home.vue`

现状：

1. 模板底部使用的是 `<StoreTabBar v-model:activeTab="activeTab" />`
2. `activeTab` 只负责在 `cart` 和 `orders` 之间切换
3. 页面没有固定的购物车金额汇总、去结算按钮，也没有和详情页一致的底部操作布局

结论：

- 用户反馈“底部没有加入购物车”本质上是：店铺首页底部缺少明确的加购结果承接与结算动作，和商品详情页体验不一致。

### 2. 店铺首页内部其实已经有一半相关能力，但没接上

同样在 `miniprogram/src/pages/store/home.vue` 中，已存在：

1. 商品列表内 `+` 按钮，调用 `addToCart(product)`
2. `goCart()` 方法
3. 一整套未接入模板的样式：
   - `.cart-bar`
   - `.cart-area`
   - `.cart-icon`
   - `.cart-badge`
   - `.cart-amount`
   - `.cart-btn`

结论：

- 页面已经具备“购物车底栏”雏形，本次实现可以优先复用已有方法和样式，而不是从零设计。

### 3. 商品详情页底部是当前统一目标

当前文件：

- `miniprogram/src/pages/store/product.vue`

现状：

1. 底部是固定操作栏 `.bottom-bar`
2. 左侧有 `首页`、`购物车`
3. 右侧有 `加入购物车`、`立即购买`
4. 有购物车角标和统一的固定底栏视觉层级

结论：

- 本次“统一”应以该页面的视觉语言为准：
  - 固定底栏
  - 清晰的左侧辅助入口
  - 明确的主动作按钮
  - 购物车角标和状态反馈

### 4. `StoreTabBar.vue` 目前仅被店铺首页使用

当前文件：

- `miniprogram/src/components/StoreTabBar.vue`

检索结果显示它目前只在：

- `miniprogram/src/pages/store/home.vue`

被引用一次。

结论：

- 若店铺首页不再使用底部 Tab 切换，本组件会变成废弃代码，需要在实现时决定删除或至少停止引用。

### 5. PRD 当前描述与目标实现不一致

`PRD.md` 当前已有明确描述：

1. 店铺首页支持“底部TabBar切换”
2. `我的订单` 作为店铺首页底部入口存在

而本轮决策已改为：

1. 店铺首页底部改为购物车结算承接栏
2. `我的订单` 迁移到页面内快捷入口

结论：

- 本次必须同步更新 `PRD.md`，否则文档与实际实现会冲突。

## Proposed Changes

### 1. 改造店铺首页底部为购物车结算栏

文件：

- `miniprogram/src/pages/store/home.vue`

改动目标：

1. 去掉底部 `StoreTabBar`
2. 接入固定购物车结算栏
3. 保留商品列表内 `+` 加购
4. 让用户在店铺首页也能明确看到“已加购结果 + 下一步动作”

具体方案：

1. 模板层
   - 删除 `<StoreTabBar v-model:activeTab="activeTab" />`
   - 在页面底部接入固定购物车栏，直接复用/调整当前文件里已存在的 `.cart-bar` 相关结构与样式
   - 底栏左侧展示：
     - 购物车图标
     - 已选数量角标
     - 已选金额汇总
   - 底栏右侧展示主按钮：
     - 购物车为空时：显示禁用态或弱化态的引导文案，不误导为可直接结算
     - 购物车非空且店铺营业中时：显示 `去结算`
     - 购物车非空但店铺休息中时：显示 `去购物车` 或不可结算提示，避免直接进入不允许提交的状态
2. 脚本层
   - 移除 `activeTab` 与对应 `watch`
   - 新增或显式接入基于 `cartStore` 的计算属性：
     - 购物车数量
     - 购物车总金额
     - 是否空购物车
     - 是否允许直接结算
   - 保留并复用现有 `addToCart(product)` 与 `goCart()`
   - 新增 `goConfirm()` 或统一的主按钮点击逻辑，在满足条件时跳转 `pages/store/confirm`
3. 样式层
   - 以 `pages/store/product.vue` 的底栏视觉为参照，统一圆角、阴影、按钮渐变、角标层级和安全区处理
   - 同步调整 `bottom-placeholder` 或底部 `padding`，避免底栏遮挡商品列表

改动原因：

1. 列表页没有“唯一当前商品”，不适合直接复制详情页的双按钮语义
2. 购物车结算栏更符合列表页的加购后承接逻辑
3. 这也是当前页面已有方法和样式基础上最小、最稳的实现路径

### 2. 将“我的订单”迁移到页面内快捷入口

文件：

- `miniprogram/src/pages/store/home.vue`

改动目标：

1. 保留用户从店铺首页进入订单列表的能力
2. 不再与底部购物车结算动作抢主入口

具体方案：

1. 在店铺首页顶部信息区下方新增页面内快捷入口区域
2. 入口位置放在：
   - `rest-tip` 下方、`main-content` 上方
   - 若店铺未休息，则放在店铺头部与 `main-content` 之间
3. 至少提供：
   - `我的订单`
4. 点击继续复用现有 `goMyOrders()` 跳转逻辑

改动原因：

1. 用户已确认 `我的订单` 迁移到页面内明显位置
2. 该位置比头图右上角更稳，不会与 `营业中/休息中` 状态标签冲突
3. 实现成本低，且对当前布局侵入更小

### 3. 清理店铺首页不再需要的 Tab 切换逻辑

文件：

- `miniprogram/src/pages/store/home.vue`
- `miniprogram/src/components/StoreTabBar.vue`

改动目标：

1. 清掉已不再符合产品口径的底部 Tab 逻辑
2. 避免后续继续误用旧组件

具体方案：

1. 从 `home.vue` 移除：
   - `StoreTabBar` 组件依赖
   - `activeTab`
   - `watch(activeTab, ...)`
2. 若确认全项目不再使用 `StoreTabBar.vue`，则删除该组件
3. 若暂不删除，也要确保它不再被 `home.vue` 引用，并在计划执行时评估是否保留为历史组件

改动原因：

1. 当前组件只服务于旧的“购物车/我的订单底部 Tab 切换”方案
2. 继续保留引用会和新方案冲突

### 4. 视情况微调商品详情页底栏样式令两页更一致

文件：

- `miniprogram/src/pages/store/product.vue`

改动目标：

1. 保证“统一”不是单向模仿，而是两页底栏在视觉上真正同体系

具体方案：

1. 仅在必要时微调以下内容：
   - 内边距
   - 安全区高度
   - 阴影
   - 图标与按钮间距
2. 不改动商品详情页现有交互语义：
   - `加入购物车`
   - `立即购买`

改动原因：

1. 用户诉求的核心是统一体验，而不是重构详情页逻辑
2. 若首页改完已足够统一，可将详情页限制为只做最小样式对齐

### 5. 同步更新 PRD 文档

文件：

- `PRD.md`

改动目标：

1. 修正文档中关于店铺首页底部 Tab 切换的旧描述
2. 保持产品文档与实现一致

具体方案：

1. 将店铺首页“底部TabBar切换”描述更新为：
   - 商品列表内支持 `+` 快速加购
   - 底部固定展示购物车汇总与去结算/去购物车动作
   - `我的订单` 作为页面内快捷入口存在
2. 若测试指南或相关页面说明中提及底部 Tab 切换，也同步改口径

改动原因：

1. 当前 PRD 已和本轮已确认方案冲突
2. 工作区规则要求功能改动后同步文档

## Assumptions & Decisions

1. 店铺首页不复制商品详情页“当前商品双按钮”交互，而是采用更适合列表页的购物车结算栏。
2. 商品加购动作继续发生在商品卡片/列表项内部的 `+` 按钮上。
3. 底部主动作优先承接“查看购物车/去结算”，而不是“立即购买当前商品”。
4. `我的订单` 迁移到页面内快捷入口，不再占用底部主操作区域。
5. 本轮优先复用 `home.vue` 内已经存在但未接线的购物车底栏样式与方法，避免无必要的大改。
6. `PRD.md` 需要同步更新，因为现文档仍写的是底部 Tab 切换方案。

## Verification Steps

实施后按以下步骤验证：

1. 页面结构验证
   - 进入 `pages/store/home?merchant_id=1`
   - 确认底部不再显示旧的“购物车 / 我的订单”双 Tab
   - 确认页面内存在明显的 `我的订单` 快捷入口
2. 空购物车验证
   - 首次进入店铺首页，不进行加购
   - 确认底部展示为空购物车态，按钮文案和可点击状态符合方案
3. 加购反馈验证
   - 在热销区和分类商品区分别点击 `+`
   - 确认底部购物车数量、金额及时更新
4. 跳转验证
   - 点击底部购物车区域，进入 `pages/store/cart`
   - 在购物车非空且可结算时，点击主按钮进入 `pages/store/confirm`
   - 点击页面内 `我的订单` 入口，进入 `pages/store/my-orders`
5. 营业状态验证
   - 在营业中和休息中商家下分别验证底部主按钮文案与可达路径
   - 确认休息中不会误导用户直接发起不可提交结算
6. 一致性验证
   - 对比 `pages/store/home` 与 `pages/store/product`
   - 确认底栏固定方式、层级、圆角、按钮风格、角标表现属于同一设计语言
7. 质量检查
   - 对修改文件执行前端诊断
   - 确认未引入模板、脚本或样式报错
