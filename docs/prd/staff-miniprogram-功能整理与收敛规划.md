# PRD-服务人员小程序端功能整理与收敛规划

## 1. 文档定位

本文档**以 PC 后台（web-admin）现有业务板块能力为准**，对服务人员小程序端（`staff-miniprogram`）功能进行全端对照整理与收敛：梳理「服务人员注册 → 审核 → 日常工作 → 健康服务 → 运维」的完整链路，标注 PC ↔ 小程序能力对应关系，并**删除/收敛小程序中与 PC 不对应或多余的功能**。

> **主要原则**：以 PC 为准。小程序端仅保留 PC 后台具有对应治理/职责能力的功能；PC 没有对应运营/管理端的功能，视为多余，建议删除或折叠。

## 2. 服务人员角色链路（概述）

```
1. 注册申请（携带资质材料）
      ↓
2. PC 后台审核（审核列表：通过/驳回，全程留痕）
      ↓
3. 登录（账号密码 / 微信快捷登录）
      ↓
4. 查看待办 / 抢单 / 被派单（PC 订单派单 → 进入「已接/待办」）
      ↓
5. 签到（开始服务）
      ↓
6. 签退（结束服务，租赁订单自动生成租后回访）
      ↓
7. 健康服务承接（档案/评估/适配建议/照护计划/照护记录/随访/体征/宣教）
      ↓
8. 接单统计 + 资料变更（需审核）+ 我的审核记录
```

## 3. 全端功能对齐对照表

| 业务板块 | PC 后台 | 服务人员小程序端 | 处置 |
|---|---|---|---|
| 工单执行 | 订单派单/核销/归还退款(merchant) | 待办、已接订单、签到、签退 | ✅ 保留 |
| 客户健康档案 | 健康服务-健康档案 | `resident`（查看档案/评估记录） | ✅ 保留 |
| 健康评估 | 健康服务-评估量表/评估记录 | `resident` 内登记评估 | ✅ 保留 |
| 康复辅具适配 | 健康服务-适配建议 | `fitting-form` 生成适配建议 | ✅ 保留 |
| 居家照护 | 健康服务-照护计划 | `care-plans`+详情、`care-visit-form` 录入照护 | ✅ 保留 |
| 康复随访 | 健康服务-随访任务 | `follow-ups`+详情(完成/跳过) | ✅ 保留 |
| 生命体征 | 健康服务-生命体征管理 | `resident` 内血压/血糖等监测 | ✅ 保留 |
| 健康宣教 | 健康服务-健康宣教 | 随访选用宣教文章 | ✅ 保留 |
| 接单统计 | 经营分析(商家整体视角) | `statistics`(服务人员个人视角) | ✅ 保留 |
| 资料与审核 | 服务人员管理、审核列表 | 资料变更(待审核)、我的审核记录 | ✅ 保留 |
| 排班 | **PC 无排班管理** | `schedule`(tab，纯占位日历) | ⚠️ 建议删除（无 PC 对应来源，多余） |
| 验机归还 | 租赁到期提醒/归还退款(PC 后台操作) | 我的页「验机归还」菜单(占位) | ⚠️ 建议删除（归还属 PC 职责，非服务人员） |
| 消息通知/设置/帮助 | PC 无对应 | 我的页「消息通知/设置/帮助反馈」(占位) | ⚠️ 建议删除或折叠（无后端来源） |

## 5. 保留功能清单（小程序端应呈现的完整功能树）

### 一级：工单（tab）
- 待办首页：今日派单/待出发/服务中/今日完成统计 + 我的待办列表
- 全部工单：
  - 待接单（可抢单）/ 已接订单（按 biz_status 筛选）
  - 工单详情：客户信息、商品明细、金额、签退操作
  - **客户健康档案入口**：`userId` → 居民档案/评估/体征
  - 签到（开始服务）→ 签退（结束服务）

### 一级：我的（tab）
- 头部：姓名、手机号、累计接单/今日接单/累计金额
- 服务人员身份：资料变更（需审核）、我的审核记录
- 列表：全部工单（跳转）；健康服务集中在工单内承接
- 退出登录

### 健康服务（由工单详情或我的入口进入，全部保留）
- 居民健康档案（查看/未建档提示）
- 健康评估（选量表答题、结果回写档案等级）
- 康复辅具适配建议（推荐商品去选购）
- 我的照护计划（列表/详情/历史照护记录）
- 录入上门照护记录
- 我的随访任务（详情/完成/跳过，含宣教选用）
- 生命体征监测（查看/录入）
