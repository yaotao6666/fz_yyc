# 商品租赁模式全栈实现计划

## 1. 摘要

为商品增加销售类型属性，区分「一口价」和「租赁」两种模式。租赁模式支持完整的租赁业务链路：商品配置租赁单价/计费周期/押金 → C端用户选择租赁时长下单 → 支付租金+押金 → 归还商品 → 商户验机退款押金。本次改造为全栈实现，覆盖数据库迁移、后端API、PC后台前端、C端小程序、PRD文档。

## 2. 当前状态分析

### 2.1 商品模型现状

- **Product struct**（`server/internal/models/models.go` 行 237-260）：仅有价格相关字段 `Price`/`OriginalPrice`/`Stock`/`Unit`，无销售类型区分
- **ProductRequest**（`server/internal/handlers/merchant/product.go` 行 430-448）：创建/更新请求无租赁字段
- **ProductResponse / StoreProductResponse**：响应结构无租赁字段
- **前端商品编辑**（`MerchantProductEditView.vue` 行 41-53）：表单只有 `price`/`original_price`/`stock` 等基础字段
- **C端商品展示**（`product.vue`/`home.vue`）：统一按一口价展示 `¥{price}`

### 2.2 订单模型现状

- **Order struct**（`models.go` 行 354-398）：`TotalAmount`/`PayAmount` 等金额字段，无押金概念
- **OrderItem struct**（`models.go` 行 404-419）：`Price`/`Quantity`/`Subtotal`，无租赁时长/押金快照
- **CreateOrder**（`user/handler.go` 行 679-994）：`subtotal = price * quantity` 简单计算，无租赁逻辑
- **订单状态**：1=待支付 2=已支付 3=已完成 4=已取消 5=退款中 6=已退款，无「租赁中」「已归还」状态

### 2.3 业务上下文

本项目为适老化商品平台，分类含「轮椅」「助行器」「拐杖类」「床边扶手」等，这些商品天然支持租赁场景。当前数据库已有「租赁类」分类（ID=17），但商品本身无租赁属性。

## 3. 目标架构定义

### 3.1 商品销售类型

| 类型 | 值 | 说明 |
|------|---|------|
| 一口价 | 1 | 固定价格售卖，用户购买后拥有商品 |
| 租赁 | 2 | 按时长计费租赁，用户支付租金+押金，归还后退押金 |

### 3.2 租赁计费周期

| 周期 | 值 | 说明 |
|------|---|------|
| 按天 | 1 | 每日计费 |
| 按周 | 2 | 每周计费 |
| 按月 | 3 | 每月计费 |

### 3.3 租赁订单流程

```
用户选择租赁商品 → 选择租赁时长 → 确认订单（租金+押金）→ 微信支付（租金+押金）
→ 订单状态：已支付（租赁中）→ 用户使用商品 → 到店/上门归还
→ 商户验机 → 完成订单（已归还）→ 退还押金（原路退款）
```

### 3.4 押金处理逻辑

- 下单时：`支付金额 = 租金总额 + 配送费 - 优惠 + 押金`
- 归还时：商户在PC后台点击「完成订单+退押金」，系统发起微信退款，退款金额 = 押金 - 扣除金额（可选）
- 若有损坏：商户可输入扣除金额，剩余押金退还用户

#### 5.4.2 订单项构建与价格计算改造（行 767-825）

对每个商品项：
1. 查询商品时获取 `SaleType`/`RentalPrice`/`Deposit`/`RentalUnit`/`MaxRentalDuration`
2. 若 `sale_type == 1`（一口价）：保持现有逻辑 `subtotal = price * quantity`
3. 若 `sale_type == 2`（租赁）：
   - 校验 `rental_duration > 0`
   - 校验 `max_rental_duration == 0 || rental_duration <= max_rental_duration`
   - `rental_subtotal = rental_price * rental_duration * quantity`
   - `item_deposit = deposit * quantity`
   - `subtotal = rental_subtotal`（用于总额累加）
   - 累加 `totalDeposit += item_deposit`
4. OrderItem 写入租赁快照字段

#### 5.4.3 支付金额计算调整（行 851-862）

### 5.5 新增归还+退押金接口

**新文件**: `server/internal/handlers/merchant/order_rental.go`

#### 5.5.1 归还租赁商品接口

```
POST /api/v1/merchant/orders/{order_id}/return
Authorization: Bearer {token}
```

**请求参数**：
```json
{
  "deduct_amount": 0,
  "remark": "验机情况说明"
}
```

**逻辑**：
1. 校验订单状态为「已支付」且包含租赁商品（`total_deposit > 0`）
2. 更新订单：`status=3`(已完成)、`rental_returned_at=now`、`rental_return_remark`
3. 若 `deduct_amount > 0`：`deposit_status=3`(部分扣除)、`deposit_deduct_amount=deduct_amount`
4. 若 `deduct_amount == 0`：`deposit_status=2`(已退)
5. `deposit_refund_amount = total_deposit - deduct_amount`
6. `deposit_refunded_at = now`
7. 若 `deposit_refund_amount > 0`：调用微信退款接口退还押金
8. 记录归还行为事件

#### 5.5.2 路由注册（`server/cmd/server/main.go`）

在商户订单路由组中新增：

## 9. 假设与决策

1. **销售类型默认值**：现有商品默认 `sale_type=1`（一口价），`rental_unit=0`、`rental_price=0`、`deposit=0`
2. **押金支付方式**：押金与租金一起通过微信支付收取，归还时通过微信退款退还
3. **租赁订单核销**：租赁订单不使用核销码，改为「归还」操作，商户在PC后台执行
4. **购物车混合**：一口价与租赁商品可同时存在于购物车，但租赁商品需选时长
5. **配送方式**：租赁商品同样支持配送/堂食/自提三种方式
6. **归还方式**：用户到店归还或商户上门取回，不在系统中单独管理物流
7. **押金扣除**：商户在归还时可选填扣除金额（损坏赔偿），系统自动计算退还金额
8. **最大租赁时长**：`max_rental_duration=0` 表示不限制，由商户自行设置上限
