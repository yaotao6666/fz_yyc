# PC服务商后台订单管理扩展计划

## Summary
- 目标：在 `web-admin/` 新增服务商“订单管理”能力，支持按商家筛选查看订单列表，并提供独立订单详情页。
- 交付范围：`只读查看`，不包含核销、退款、改状态等订单操作。
- 关键决策：
  - 前端新增独立菜单与路由：`/orders`、`/orders/:id`
  - 后端允许新增服务商侧订单接口
  - 后端查询逻辑优先复用商家侧现有订单列表/详情实现，避免重复造方法
  - 订单筛选首批支持：`merchant_id`、`status`、`start_date`、`end_date`、`keyword(订单号)`

## Current State Analysis
- `web-admin` 当前没有独立订单页面与菜单，现有路由仅包含工作台、商家、公告、分账、分析、设置：
  - `web-admin/src/router/index.ts`
  - `web-admin/src/layouts/AppLayout.vue`
- `web-admin` 现有最接近订单列表的页面是 `分账历史`，已经沉淀了可复用的商家筛选、状态筛选、日期区间、分页表格骨架：
  - `web-admin/src/views/settlement/ProfitSharingHistoryView.vue`
- 服务商侧后端目前只有订单分析与退款列表接口，没有服务商订单列表/详情接口：
  - 已有：`GET /api/v1/sp/orders/analytics`
  - 已有：`GET /api/v1/sp/orders/refunds`
  - 缺失：`GET /api/v1/sp/orders`
  - 缺失：`GET /api/v1/sp/orders/:order_id`
  - 路由文件：`server/cmd/server/main.go`
- 商家侧已经存在成熟的订单列表/详情逻辑，可直接抽公共查询能力复用：
  - 列表：`server/internal/handlers/merchant/order.go` 中 `GetOrders`
  - 详情：`server/internal/handlers/merchant/order.go` 中 `GetOrderDetail`
  - 已包含图片私有化、退款状态刷新、`Preload("User").Preload("Items")` 等逻辑
- 商家端现有订单页面已定义了本次 PC 端可沿用的展示字段与筛选习惯：
  - 列表页：`miniprogram/src/pages/merchant/orders/list.vue`
  - 详情页：`miniprogram/src/pages/merchant/orders/detail.vue`
  - 类型定义：`miniprogram/src/types/index.ts`

## Assumptions & Decisions
- 仅新增服务商后台的只读订单查看能力，不改变商家端订单操作职责边界。
- 服务商只能看到自己名下商家的订单，所有服务商订单查询都必须附带 `service_provider_id` 约束。
- 复用商家侧订单查询逻辑的方式不是直接跨 handler 调用，而是抽出公共查询/组装层，供 `merchant` 与 `sp` 两侧 handler 共同调用。
- PC 端首版订单列表默认按 `created_at DESC` 排序，分页默认 `page=1`、`page_size=20`。
- 首版独立详情页展示订单基础信息、商品明细、用户信息、配送信息、支付与核销信息、金额明细；不新增编辑能力。
- 前端筛选交互对齐现有项目风格：
  - 商家：下拉选择，复用现有商家列表接口数据源
  - 状态：全部/待支付/已支付/已完成/已取消/退款中/已退款
  - 时间：日期区间选择器
  - 关键词：订单号模糊查询
- 日期区间非法时前端阻止查询，和现有订单筛选规范保持一致。

## Proposed Changes

### 1. 抽取后端公共订单查询层
- 新增目录与文件：
  - `server/internal/services/orderquery/query.go`
- 变更内容：
  - 抽出“订单列表查询”“订单详情查询”“订单图片私有化”“退款状态刷新”公共方法
  - 定义服务于 `merchant` 与 `sp` 的统一查询参数结构，例如：
    - `MerchantID`
    - `MerchantIDs`
    - `Status`
    - `DeliveryType`
    - `StartDate`
    - `EndDate`
    - `Keyword`
    - `Page`
    - `PageSize`
  - 定义统一返回结构，保持与现有商家侧返回口径兼容：
    - 列表：`list + pagination`
    - 详情：单个订单对象
- 为什么这么做：
  - 满足“尽量复用商家查看订单列表函数，避免重复造方法”
  - 避免 `merchant` 包与 `sp` 包互相依赖 handler
  - 后续若再扩展退款详情、订单导出，也能沿用同一查询层

### 2. 重构商家侧订单 handler 以复用公共层
- 修改文件：
  - `server/internal/handlers/merchant/order.go`
- 变更内容：
  - `GetOrders` 改为调用 `orderquery` 公共列表查询
  - `GetOrderDetail` 改为调用 `orderquery` 公共详情查询
  - 保持现有商家接口路径与返回结构不变，确保小程序无感升级
- 为什么要改：
  - 先把现有商家实现沉淀为共享逻辑，再供 SP 接口复用，避免复制粘贴查询代码

### 3. 新增服务商侧订单列表/详情接口
- 新增文件：
  - `server/internal/handlers/sp/order.go`
- 修改文件：
  - `server/cmd/server/main.go`
- 新增接口：
  - `GET /api/v1/sp/orders`
  - `GET /api/v1/sp/orders/:order_id`
- 列表接口设计：
  - 查询参数：
    - `page`
    - `page_size`
    - `merchant_id`
    - `status`
    - `start_date`
    - `end_date`
    - `keyword`
  - 权限约束：
    - 若传入 `merchant_id`，先校验该商家属于当前服务商
    - 若未传 `merchant_id`，则只查询当前服务商名下全部商家订单
  - 返回结构：
    - `list`
    - `pagination.total`
    - `pagination.page`
    - `pagination.page_size`
  - 单条订单建议包含字段：
    - `id`
    - `order_no`
    - `merchant`
    - `user`
    - `items`
    - `total_amount`
    - `delivery_fee`
    - `discount_amount`
    - `pay_amount`
    - `delivery_type`
    - `status`
    - `verify_code`
    - `transaction_id`
    - `created_at`
    - `paid_at`
    - `completed_at`
    - `completed_by_name`
    - `refunded_at`
- 详情接口设计：
  - 按 `order_id + service_provider_id` 校验归属
  - 返回结构直接复用商家订单详情结构
- 为什么拆成独立 `sp/order.go`：
  - 当前 `server/internal/handlers/sp/handler.go` 已较大，订单能力拆文件更便于维护

### 4. 扩展前端类型与 API 封装
- 修改文件：
  - `web-admin/src/types/sp.ts`
  - `web-admin/src/api/sp.ts`
- 类型新增：
  - `SpOrderUser`
  - `SpOrderMerchant`
  - `SpOrderItem`
  - `SpOrder`
  - `SpOrderListResponse`
- API 新增：
  - `getSpOrders(params)`
  - `getSpOrderDetail(orderId)`
- 设计原则：
  - 尽量与小程序侧 `Order` 结构对齐，减少状态/字段解释分裂
  - 仅补 PC 端真正要用到的字段，不额外制造冗余 DTO

### 5. 新增订单管理列表页
- 新增文件：
  - `web-admin/src/views/order/OrderListView.vue`
- 页面结构：
  - 顶部标题区：说明“按商家、状态、日期、订单号查看订单”
  - 筛选区：
    - 商家下拉
    - 订单状态下拉
    - 日期区间
    - 订单号输入框
    - 查询/重置按钮
  - 列表区：
    - 订单号
    - 商家名称
    - 用户昵称/手机号
    - 订单金额
    - 配送方式
    - 订单状态
    - 下单时间
    - 操作列“查看详情”
  - 分页区：复用现有分页风格
- 复用点：
  - 商家筛选加载逻辑复用 `ProfitSharingHistoryView.vue` 的 `loadMerchantOptions`
  - 列表筛选/分页布局复用 `ProfitSharingHistoryView.vue`
  - 金额/时间格式化复用 `web-admin/src/utils/format.ts`
- 交互细节：
  - 若从商家详情页进入，可预留接受 `merchant_id` query 并自动带筛选
  - 日期开始晚于结束时前端提示并阻止请求

### 6. 新增订单详情页
- 新增文件：
  - `web-admin/src/views/order/OrderDetailView.vue`
- 页面内容：
  - 状态摘要卡
  - 订单信息：订单号、下单时间、支付时间、支付单号、核销码、核销时间、核销人
  - 商家信息：商家名称、地址、联系电话
  - 用户信息：昵称、手机号
  - 配送信息：配送方式、地址、联系人、距离
  - 商品清单：图片、商品名、规格、单价、数量、小计
  - 金额明细：商品金额、配送费、优惠、实付
- 路由参数：
  - `:id`
- 跳转关系：
  - 订单列表 -> 订单详情
  - 后续可从商家详情页加“查看该商家订单”入口，但本次不是必做项

### 7. 注册前端路由与菜单
- 修改文件：
  - `web-admin/src/router/index.ts`
  - `web-admin/src/layouts/AppLayout.vue`
- 路由新增：
  - `/orders`
  - `/orders/:id`
- 菜单新增：
  - 侧边栏新增 `订单管理`
- 菜单高亮规则：
  - `route.path.startsWith('/orders')` 时高亮 `订单管理`
- 菜单位置：
  - 放在 `商家列表` 之后、`公告管理` 之前，符合业务优先级

## Implementation Steps
1. 在 `server/internal/services/` 下新增公共订单查询模块，完成查询参数、列表查询、详情查询、图片签名与退款状态刷新封装。
2. 将 `server/internal/handlers/merchant/order.go` 改为调用公共订单查询层，保证商家端接口返回不变。
3. 新增 `server/internal/handlers/sp/order.go`，实现服务商订单列表与详情接口，并在 `server/cmd/server/main.go` 注册路由。
4. 扩展 `web-admin/src/types/sp.ts` 与 `web-admin/src/api/sp.ts`，补订单列表/详情类型和 API。
5. 基于 `ProfitSharingHistoryView.vue` 的筛选表格结构，实现 `OrderListView.vue`。
6. 基于小程序订单详情字段，实现 `OrderDetailView.vue`。
7. 更新 `web-admin/src/router/index.ts` 与 `web-admin/src/layouts/AppLayout.vue`，接入订单菜单与页面路由。
8. 更新 PRD/接口文档/业务链路文档，保证服务商 PC 后台能力口径一致。
