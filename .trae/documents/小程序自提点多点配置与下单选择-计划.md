# 小程序自提点多点配置与下单选择：实施计划

## Summary

在现有“小程序商家端配送设置 + C端下单页配送方式选择”的基础上，增加“自提点”能力：

- 商家端：开启自提后，可配置多个自提点（地图选点录入经纬度），并设置默认自提点
- C端下单页：当用户选择“自提”时，必须选择一个自提点（确认页内弹窗选择）
- 后端与数据库：新增自提点表；订单在自提模式下写入所选自提点（含快照字段），用于后续订单查看/履约

## Current State Analysis

### 1) 现有“下单方式”开关

- 商家开关字段存储在 `merchants` 表：`takeout_enabled / dine_in_enabled / pickup_enabled`  
  见：[20240101000000_full_init.sql](file:///e:/yt/fz_yyc/server/migrations/20240101000000_full_init.sql#L90-L110)
- 商家端页面已支持“开启自提”开关，但没有“自提点”配置：  
  [delivery-settings.vue](file:///e:/yt/fz_yyc/miniprogram/src/pages/merchant/delivery-settings.vue#L1-L60)
- C端下单页（确认订单）根据 `pickup_enabled` 决定是否展示“自提”方式，但无自提点选择：  
  [confirm.vue](file:///e:/yt/fz_yyc/miniprogram/src/pages/store/confirm.vue#L187-L390)

### 2) 现有配送规则接口与下单接口

- C端可公开获取配送规则（含三种模式开关）：  
  `GET /api/v1/store/:merchant_id/delivery-rules`  
  后端实现：[GetDeliveryRules](file:///e:/yt/fz_yyc/server/internal/handlers/user/handler.go#L496-L540)
- C端创建订单：  
  `POST /api/v1/store/:merchant_id/orders`  
  后端对 `delivery_type==3(自提)` 仅校验商家是否开启自提，并清空配送地址/联系人字段：  
  [CreateOrder](file:///e:/yt/fz_yyc/server/internal/handlers/user/handler.go#L678-L749)
- 订单模型目前仅有配送地址/联系人等字段，没有自提点字段：  
  [Order](file:///e:/yt/fz_yyc/server/internal/models/models.go#L331-L366)

## Assumptions & Decisions

- 自提点字段：名称 + 地址 + 经纬度（用户已确认）
- 默认规则：商家可设置 1 个默认自提点，下单页自提默认选中（用户已确认）
- 自提订单不额外要求用户填写联系人/电话（保持现状，用户已确认）
- 经纬度录入方式：商家端通过地图选点（`uni.chooseLocation`）（用户已确认）
- C端选择交互：确认页内弹窗选择（用户已确认）
- 订单存储策略：订单表保存 `pickup_point_id`，并冗余保存自提点快照（名称/地址/经纬度），避免后续自提点被修改/删除导致历史订单缺失

## Proposed Changes

### A) 数据库：新增自提点表 + 订单字段

1. 新增表 `merchant_pickup_points`
   - 字段建议：
     - `id` BIGINT UNSIGNED PK
     - `merchant_id` BIGINT UNSIGNED（索引）
     - `name` VARCHAR(64) NOT NULL
     - `address` VARCHAR(256) NOT NULL
     - `lat` DECIMAL(10,6) NOT NULL
     - `lng` DECIMAL(10,6) NOT NULL
     - `is_default` TINYINT(1) NOT NULL DEFAULT 0（同商家仅允许一个为 1）
     - `status` TINYINT UNSIGNED NOT NULL DEFAULT 1（1=启用 0=停用）
     - `sort` INT UNSIGNED NOT NULL DEFAULT 0
     - `created_at / updated_at`
   - 迁移文件：新增 `server/migrations/20xxxxxx_pickup_points.sql`

2. 扩展 `orders` 表（自提订单写入）
   - 新增字段建议：
     - `pickup_point_id` BIGINT UNSIGNED NULL（索引）
     - `pickup_point_name` VARCHAR(64) DEFAULT NULL
     - `pickup_point_address` VARCHAR(256) DEFAULT NULL
     - `pickup_point_lat` DECIMAL(10,6) DEFAULT NULL
     - `pickup_point_lng` DECIMAL(10,6) DEFAULT NULL

### B) 后端：模型与接口

1. 模型
   - `server/internal/models/models.go`
     - 新增 `MerchantPickupPoint` 模型（TableName: `merchant_pickup_points`）
     - 扩展 `Order` 模型增加自提点字段（与 DB 对应）

2. 商家端接口（需要商家登录）
   - 路由挂载位置：`server/cmd/server/main.go` 的 `merchantGroup`  
     参考已有配送设置接口：[main.go](file:///e:/yt/fz_yyc/server/cmd/server/main.go#L140-L216)
   - 接口设计（REST）：
     - `GET /api/v1/merchant/pickup-points`：列表（按 `is_default desc, sort asc, id desc`）
     - `POST /api/v1/merchant/pickup-points`：新增（允许传 `is_default`；若为默认则同事务内清理同商家其他默认）
     - `PUT /api/v1/merchant/pickup-points/:id`：编辑（同上，若设置为默认则清理其他默认）
     - `DELETE /api/v1/merchant/pickup-points/:id`：删除（若删除的是默认点，则自动把“最新/最小 sort”的一个点设为默认；若无剩余则不设）
   - Handler 落点：
     - 新增 `server/internal/handlers/merchant/pickup_points.go`（或放入现有 `handler.go` 同包，保持项目风格）

3. C端接口（公开可访问）
   - 路由挂载位置：`server/cmd/server/main.go` 的 `storeGroup`（目前已有 `/delivery-rules`）  
     [main.go](file:///e:/yt/fz_yyc/server/cmd/server/main.go#L110-L123)
   - 新增：
     - `GET /api/v1/store/:merchant_id/pickup-points`：返回启用的自提点列表（默认点排第一）

4. 下单写入自提点（关键）
   - 修改 `server/internal/handlers/user/handler.go`
     - 扩展 `CreateOrderRequest` 增加 `pickup_point_id`
     - 当 `delivery_type == 3`：
       - 校验 `pickup_point_id > 0`
       - 校验该自提点存在、属于该商家、且启用
       - 写入订单的 `pickup_point_id` 与快照字段（name/address/lat/lng）
     - 仍保持：自提模式清空 `delivery_address/contact_*`（保持现状）

5. 订单返回结构
   - `buildAccessibleOrder()` 目前仅处理图片与核销码；不影响自提点字段，但需要保证：
     - C端订单详情/列表返回包含新增字段
     - 商家端订单详情返回包含新增字段（便于履约）

### C) 小程序：商家端配置 UI

目标：在现有 [delivery-settings.vue](file:///e:/yt/fz_yyc/miniprogram/src/pages/merchant/delivery-settings.vue) 内增加“自提点管理”区域。

1. 页面交互
   - 当 `pickup_enabled` 为 true 时展示“自提点”section：
     - 自提点列表（默认标识、启用/停用、编辑、删除、设为默认）
     - “新增自提点”按钮
   - 新增/编辑自提点：
     - 点击“地图选点”按钮触发 `uni.chooseLocation`，回填地址与经纬度
     - 名称允许用户修改（chooseLocation 返回 name 可作为默认值）

2. 前端 API
   - 在 `miniprogram/src/api/index.ts`（商家端）增加：
     - `getPickupPoints() / createPickupPoint() / updatePickupPoint() / deletePickupPoint()`
   - 在 `miniprogram/src/types/index.ts` 增加 `MerchantPickupPoint` 类型

### D) 小程序：C端确认订单页选择自提点

目标：在 [confirm.vue](file:///e:/yt/fz_yyc/miniprogram/src/pages/store/confirm.vue) 中，当 `deliveryType === 3` 时要求选择自提点。

1. 数据加载
   - 新增 store API：`getStorePickupPoints(merchantId)`
   - 页面进入/切换商家时加载自提点列表

2. 交互与校验
   - 当用户切换到“自提”：
     - 若有默认自提点：自动选中
     - 若无可用自提点：提示“请商家配置自提点”，并禁止提交
   - 自提点选择弹窗（确认页内弹窗）：
     - 展示列表（名称、地址、默认标识）
     - 选择后关闭弹窗并更新当前选中
     - 可加“一键导航”按钮：调用 `uni.openLocation({ latitude, longitude, name, address })`（基于你已选择经纬度）

3. 下单请求
   - 扩展 `CreateOrderRequest`（小程序 types）增加 `pickup_point_id`
   - `createOrder()` 调用时：
     - `delivery_type == 3` 必传 `pickup_point_id`

### E) 兼容与边界场景

- 商家关闭自提：C端不显示自提；不影响历史自提订单
- 删除自提点：
  - 若仍存在引用该点的历史订单：因为订单已存快照，不影响展示
  - 若删除默认点：按“剩余点自动补默认”的规则处理
- 自提点停用：C端列表不返回停用点；若用户仍选中停用点则提交前校验失败并提示重新选择
