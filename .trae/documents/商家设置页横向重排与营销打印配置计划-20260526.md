# 商家设置页横向重排与营销打印配置计划

## Summary
- 目标：重排 `pages/merchant/settings`，改成更适合承载多功能入口的横向/宫格化布局；同时新增商家端“满减营销”能力，并接入“飞鹅打印机配置与开关”管理。
- 已确认的范围：
  - `settings` 页面改为“顶部商家信息卡 + 下方功能九宫格/多列入口”
  - 营销功能要做到“商家可配置多档满减，用户下单实际生效”
  - 飞鹅打印机走“复用现有打印机 CRUD，同时扩展表字段支持飞鹅专属参数”的方案
- 本次不做：
  - 复杂营销体系（优惠券领取、限时活动、商品级营销）
  - 真正调用飞鹅开放平台下发打印任务
  - 订单自动打印编排与模板体系

## Current State Analysis
- `miniprogram/src/pages/merchant/settings.vue` 当前是纵向分组列表：
  - 商家信息
  - 账号安全
  - 店铺运营
  - 退出登录
- 当前设置页仅作为入口页，能跳转：
  - `delivery-settings`
  - `notification-settings`
  - `staff`
  - `settlements/history`
- 当前设置页 API 只拉 `getMerchantSettings()`，类型为 `MerchantSettings`：
  - 已有字段：公告、营业时间、起送价、配送/堂食/自提开关、提醒开关、微信绑定信息
  - 文件：
    - `miniprogram/src/api/index.ts`
    - `miniprogram/src/types/index.ts`
- 当前小程序商家端没有现成的营销页、优惠券页、打印机页：
  - `miniprogram/src/pages/merchant/` 下仅有 `settings/home/delivery-settings/categories/notification-settings/staff`
- 后端商家侧已存在打印机 CRUD 与打印日志接口：
  - `GET/POST/PUT/DELETE /api/v1/merchant/printers`
  - `POST /api/v1/merchant/printers/:printer_id/test`
  - `GET /api/v1/merchant/print-logs`
  - 文件：`server/internal/handlers/merchant/printers.go`, `server/internal/handlers/merchant/print_logs.go`
- 后端打印机模型 `CloudPrinter` 当前字段：
  - `name`
  - `brand(type)`
  - `device_no`
  - `api_key`
  - `api_url`
  - `print_types`
  - `status`
  - `auto_print`
  - `is_default`
  - `print_count`
  - `last_print_at`
  - 文件：`server/internal/models/models.go`
- 后端已有 `Coupon` 模型，但语义更接近“用户领取型优惠券”，并没有商家侧营销管理接口，也没有下单自动满减计算逻辑：
  - `server/internal/models/models.go`
  - 当前下单流程 `CreateOrder` 只算商品金额 + 配送费，没有营销优惠计算：
    - `server/internal/handlers/user/handler.go`
- 文档侧对“商家设置”有约束，但没有“满减营销/打印机/飞鹅打印机”的明确口径，需要在实施时同步补文档。

## Assumptions & Decisions
- `settings` 页面不再承载大量表单，而是作为“商家工作台入口页”，以九宫格/多列卡片形式承载更多功能按钮。
- 顶部仍保留商家信息概览卡，避免纯宫格后店铺信息入口丢失。
- 满减采用“多档规则 + 自动取最优档”的策略，例如：
  - 满 50 减 5
  - 满 100 减 15
- 满减是自动营销，不走“领券/选券”，因此不复用现有 `Coupon` 作为主模型，而是新增独立“商家满减规则”数据结构。
- 用户下单页与订单创建接口都要感知满减：
  - 用户确认页展示满减优惠
  - 后端 `CreateOrder` 重新计算并写入 `discount_amount`
  - 最终 `pay_amount = total_amount + delivery_fee - discount_amount`
- 飞鹅打印机以现有 `cloud_printers` 为基础扩展字段，采用“通用字段 + 飞鹅专属字段”混合模型。
- 飞鹅专属字段优先按常见接入参数设计：
  - `feie_user`
  - `feie_ukey`
  - `feie_sn`
  - 保留现有 `device_no/api_key/api_url/brand/auto_print/status`
- 本次“打印机开关”优先落在：
  - 打印机启停（`status`）
  - 自动打印开关（`auto_print`）
  - 默认打印机开关（`is_default`）
- 不在本次计划中实现真实第三方打印调用，测试打印继续沿用现有“写日志 + 更新计数”的验证方式。

## Proposed Changes

### 1. 重排商家设置页为信息卡 + 功能宫格
- 修改文件：
  - `miniprogram/src/pages/merchant/settings.vue`
- 修改内容：
  - 顶部保留商家信息卡：店铺名称、联系电话、微信绑定状态、当前营业模式摘要
  - 下方改成多列功能宫格/横向按钮区，而不是单列列表
  - 按功能分组展示：
    - 店铺运营：配送设置、声音提醒、员工管理
    - 营销中心：满减营销
    - 设备服务：飞鹅打印机、打印日志
    - 账号安全：修改密码、微信快捷登录
  - 退出登录区继续保留，但弱化为底部独立按钮
- 为什么这样改：
  - 用户明确要求“横向排版，能多放一些按钮”
  - 未来还能继续扩展更多功能入口，不必每次再改设置页结构

### 2. 新增商家满减营销数据模型与接口
- 新增后端模型建议：
  - `MerchantFullReductionRule`
- 新增迁移建议：
  - 新建表 `merchant_full_reduction_rules`
- 建议字段：
  - `id`
  - `merchant_id`
  - `threshold_amount`
  - `discount_amount`
  - `sort`
  - `status`
  - `created_at`
  - `updated_at`
- 新增接口建议：
  - `GET /api/v1/merchant/full-reduction-rules`
  - `PUT /api/v1/merchant/full-reduction-rules`
- 接口语义：
  - `GET` 返回当前商家所有启用/配置中的满减规则
  - `PUT` 采用整包覆盖方式提交规则数组，便于前端多档编辑
- 为什么不用 `Coupon`：
  - 当前 `Coupon` 是领券型模型，有发行量、限领、领取记录等复杂语义
  - 自动满减是店铺级结算规则，不应该绑定用户领券流程

### 3. 新增商家营销配置页
- 新增文件：
  - `miniprogram/src/pages/merchant/marketing.vue`
- 修改文件：
  - `miniprogram/src/pages.json`
  - `miniprogram/src/api/index.ts`
  - `miniprogram/src/types/index.ts`
- 页面职责：
  - 展示多档满减规则
  - 新增一档规则
  - 删除一档规则
  - 开关启用/停用规则
  - 保存整套规则
- 页面交互建议：
  - 规则项形式：满 `X` 元，减 `Y` 元
  - 支持最多若干档（如 5 档），避免页面无限膨胀
  - 校验：
    - `threshold_amount > 0`
    - `discount_amount > 0`
    - `discount_amount < threshold_amount`
    - 多档按门槛升序且不重复
- 为什么做独立页：
  - 满减配置有较多输入与校验，独立页比塞进 `settings` 宫格页更稳定

### 4. 让满减在用户下单页与后端下单接口生效
- 修改文件：
  - `server/internal/handlers/user/handler.go`
  - `miniprogram/src/pages/store/confirm.vue`
  - `miniprogram/src/types/index.ts`
  - 若需要：`miniprogram/src/api/store.ts`
- 后端改动：
  - 在 `CreateOrder` 中，商品金额 `totalAmount` 计算完成后，按当前商家启用的满减规则计算最优优惠
  - 写入 `order.discount_amount`
  - 重新计算 `pay_amount`
  - 订单响应中返回新的金额结构
- 前端改动：
  - 确认页金额区增加“满减优惠”行
  - 若命中满减，展示具体优惠金额
  - 实付金额展示为：商品金额 + 配送费 - 优惠金额
- 兼容约束：
  - 堂食/自提/配送都可参与满减，除非你后续再细化规则
  - 若无满减规则，`discount_amount = 0`

### 5. 扩展云打印机模型以承载飞鹅配置
- 修改文件：
  - `server/internal/models/models.go`
  - 新增 migration
  - `server/internal/handlers/merchant/printers.go`
- 扩展字段建议：
  - `feie_user`
  - `feie_ukey`
  - `feie_sn`
- 更新点：
  - 创建/更新打印机请求结构增加飞鹅扩展字段
  - 返回打印机列表时：
    - 可返回 `feie_user`
    - `feie_ukey` 应按敏感字段处理，建议不明文返回
    - `feie_sn` 可返回
  - `brand/type=feie` 时校验飞鹅必填参数
- 为什么保留通用字段：
  - 当前 `cloud_printers` 已上线并可被其它品牌复用
  - “通用 + 扩展”能兼顾未来多品牌和当前飞鹅落地

### 6. 新增商家打印机管理页
- 新增文件：
  - `miniprogram/src/pages/merchant/printers.vue`
- 修改文件：
  - `miniprogram/src/pages.json`
  - `miniprogram/src/api/index.ts`
  - `miniprogram/src/types/index.ts`
- 页面职责：
  - 查看打印机列表
  - 新增飞鹅打印机
  - 编辑打印机参数
  - 开关打印机状态
  - 开关自动打印
  - 设置默认打印机
  - 触发测试打印
- 页面展示建议：
  - 打印机名称
  - 品牌
  - 设备编号 / 飞鹅 SN
  - 是否启用
  - 是否自动打印
  - 是否默认
  - 最后打印时间
- 页面交互建议：
  - 列表卡片 + 底部新增按钮
  - 新增/编辑走同页弹出层或独立子页，优先选单页表单

### 7. 可选补充打印日志查看页
- 新增文件：
  - `miniprogram/src/pages/merchant/print-logs.vue`
- 说明：
  - 若设置页宫格包含“打印日志”，可新增轻量列表页直接复用现有 `GET /api/v1/merchant/print-logs`
  - 若本次控制范围，也可以先只放“打印机管理”入口，不单独新增日志页
- 基于用户“能多放按钮”的诉求，建议宫格先放入口，但实现优先级可低于“飞鹅打印机配置”

### 8. 同步商家设置接口摘要信息
- 修改文件：
  - `server/internal/handlers/merchant/handler.go`
  - `miniprogram/src/types/index.ts`
- 建议：
  - `getMerchantSettings()` 返回中补充：
    - 满减规则是否启用/已配置摘要
    - 打印机是否已配置摘要
  - 这样 `settings` 宫格卡片能展示状态，不用每次点击后才知道是否已配置
- 若实施成本较高，也可在前端首次仅做静态入口，不把摘要塞回 `MerchantSettings`

## Implementation Steps
1. 重构 `pages/merchant/settings.vue`，将现有纵向列表改成“顶部信息卡 + 功能宫格”。
2. 新增商家满减规则模型、迁移、接口与前端类型/API。
3. 新增 `pages/merchant/marketing.vue`，支持多档满减的增删改与保存。
4. 在用户下单后端 `CreateOrder` 中接入满减最优档计算，并写入 `discount_amount/pay_amount`。
5. 在 `pages/store/confirm.vue` 中展示满减优惠与新的实付金额。
6. 扩展 `cloud_printers` 模型与 `printers.go`，支持飞鹅扩展字段。
7. 新增 `pages/merchant/printers.vue`，接入现有打印机 CRUD，并补飞鹅字段编辑、开关与测试打印。
8. 视范围决定是否补 `print-logs.vue` 与 `merchant settings` 摘要状态。
9. 同步更新 PRD/接口文档/测试口径。

## Verification Steps
- 小程序前端：
  - `pages/merchant/settings` 页面可正常显示顶部信息卡和横向功能入口
  - 点击宫格可进入营销页、打印机页、配送设置、提醒设置、员工管理
  - `miniprogram` 执行 `npm run build:mp-weixin`
- 营销功能：
  - 商家可配置多档满减规则并保存
  - 非法规则被前端拦截，如门槛重复、优惠金额大于门槛
  - 用户确认页可展示命中的满减优惠
  - 创建订单后，订单 `discount_amount/pay_amount` 与规则一致
- 打印机功能：
  - 商家可新增/编辑飞鹅打印机
  - 可切换 `status`、`auto_print`、`is_default`
  - 测试打印仍可成功落日志并更新时间/次数
- 后端：
  - `go test ./...`
  - 若暂无针对性测试，至少保证新增 handler 和 migration 后编译通过
- 文档：
  - 商家设置、满减营销、飞鹅打印机接口说明与页面说明同步完成

## Risks & Notes
- 当前 `Coupon.Type` 注释与 seed 数据存在不一致，但本计划不建议硬复用 `Coupon` 做自动满减，否则会放大既有语义混乱。
- 如果后续真要对接飞鹅真实打印，当前“通用 + 扩展字段”模型仍需补 provider 适配层，不建议把真实飞鹅调用和本次设置页改版绑在一个阶段。
- 满减下单生效会影响订单金额计算，必须以后端重算为准，前端只能展示试算结果，不能作为最终结算依据。

## Out Of Scope
- 用户领券、发券、核销券
- 满减按商品、按分类、按时间段、按会员等级等复杂规则
- 飞鹅真实云打印下发与状态查询
- 打印模板、厨房单/后厨单拆分
- 商家后台承接营销与打印配置
