# 小程序测试指南与服务商入口修正计划

## Summary

目标：完善 `PRD.md` 中 `## 9. 小程序测试指南` 板块，补齐服务商、商家、C 端三类小程序测试入口与使用步骤，并修正当前导致“找不到服务商入口”的小程序开发调试入口配置。

本次执行范围包含文档与入口配置两部分：

1. 更新 `PRD.md` 第 9 章，确保测试说明与当前代码实现一致。
2. 修正小程序源码中的编译模式配置，让“服务商入口”在源配置中表达清晰。
3. 修正当前开发产物中的微信开发者工具私有配置，让本地立即可见的“服务商”入口指向正确页面。

## Current State Analysis

### 1. `PRD.md` 第 9 章现状

已确认 `PRD.md` 当前 `## 9. 小程序测试指南` 主要覆盖的是 C 端店铺测试：

1. `9.1` 只写了“商家端测试账号（开发环境）”，未补充服务商测试账号。
2. `9.2` 与 `9.3` 均围绕 `pages/store/test-entry` 和 `pages/store/home?merchant_id=...` 展开，核心是 C 端店铺访问测试。
3. 当前章节没有明确写出服务商真实入口页面、服务商测试账号、服务商可测试功能，也没有解释商家端与服务商端入口的区别。

结论：第 9 章标题是“小程序测试指南”，但内容实际偏向 C 端测试说明，缺少服务商入口与多端测试导航，容易让使用者误以为系统没有服务商入口。

### 2. 服务商真实入口已存在于源码

已确认以下事实：

1. `miniprogram/src/pages/sp/login.vue` 为真实的服务商登录页。
2. `miniprogram/src/pages.json` 已注册服务商页面：
   - `pages/sp/login`
   - `pages/sp/home`
   - `pages/sp/merchants/*`
   - `pages/sp/announcements/*`
   - `pages/sp/analytics/merchant-stats`
   - `pages/sp/settings`
3. `miniprogram/src/pages.json` 的 `condition.list` 中当前已有一项：
   - 名称：`服务商登录`
   - 路径：`pages/sp/login`

结论：服务商功能未丢失，问题不是页面不存在，而是测试说明和开发者工具入口认知不清晰。

### 3. 当前“找不到服务商入口”的直接原因

已确认当前开发产物 `miniprogram/dist/dev/mp-weixin/project.private.config.json` 中存在微信开发者工具私有编译模式配置：

1. 名称为 `服务商` 的配置当前指向：
   - `pages/store/home`
2. 该页面是 C 端店铺首页，不是服务商登录页。
3. `pages/store/home` 依赖 `merchant_id` 参数，且没有服务商登录语义，因此会误导测试人员。
4. 同一个项目中，源码配置 `pages.json` 与开发产物私有配置对“服务商入口”的指向不一致。

结论：用户当前感知到“服务商入口找不到”，高度疑似来自微信开发者工具私有编译模式项配置错误，而不是服务商业务代码缺失。

### 4. 测试账号口径

已核对以下文档与项目记忆：

1. `测试账号文档.md` 明确服务商管理员账号为 `admin / admin123`。
2. `测试账号文档.md` 明确商家员工账号为 `merchant / merchant123`。
3. 项目当前初始化口径仅保留这两组测试账号。

结论：第 9 章可直接采用以下统一口径：

1. 服务商测试账号：`admin / admin123`
2. 商家测试账号：`merchant / merchant123`
3. C 端测试通过测试入口页或携带 `merchant_id` 的编译模式进入
