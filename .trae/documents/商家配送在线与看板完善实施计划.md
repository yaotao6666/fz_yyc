# 商家配送在线与看板完善实施计划

## Summary

本次计划围绕 5 个目标推进，并同步更新 `PRD.md`：

1. 修正商家配送设置与 C 端下单距离选择链路，明确“商家自定义档位 + 用户手动选择”，不接第三方地图。
2. 调整商家在线与提醒策略为“登录即在线”，拆分下单提醒与浏览提醒，新增独立声音管理子页面和测试播放按钮。
3. 补齐账号安全与快捷登录：修改密码弹窗、员工绑定微信快捷登录、登录页快捷登录入口。
4. 在轻量方案下补齐员工管理页面，首版仅 `owner` 可管理员工。
5. 基于现有订单统计与已收集的访问/行为数据修正商家数据看板，并把最新实现口径同步进 `PRD.md`。

已确认的产品决策：

1. 本轮取消商家优惠券与营销配置改动。
2. 商家只要登录就保持 WebSocket 在线；休息中也继续接收“顾客浏览”提醒。
3. 商家休息只阻止新的创建订单，不阻止用户浏览，也不影响支付中的订单完成支付。
4. 员工管理首版仅 `owner` 可见和可操作。
5. 修改密码成功后立即退出并重新登录。

## Current State Analysis

### 1. 配送设置已有接口，但前后端都没有形成稳定闭环

- `miniprogram/src/pages/merchant/delivery-settings.vue` 已对接 `getDeliverySettings` / `updateDeliverySettings`，但页面仅做了最基础的增删规则，没有前端合法性校验。
- `server/internal/handlers/merchant/handler.go` 已提供 `GetDeliverySettings` / `UpdateDeliverySettings`，但当前保存逻辑还需要补充区间合法性校验和明确错误语义。
- `miniprogram/src/pages/store/confirm.vue` 仍然按 `0.5km` 固定递增生成距离选项，并且配送费在前端写死计算。
- `server/internal/handlers/user/handler.go` 的 `CreateOrder` 已按配送设置计算费用，但还没有结合“商家休息禁止新下单”的新业务规则处理。

### 2. 商家设置页仍是导航壳，核心能力没有承接

- `miniprogram/src/pages/merchant/settings.vue` 当前只有商家信息、配送设置、订单提示音、二维码、数据看板等基础项。
- “修改密码”没有点击行为；“订单提示音”仍是单一开关，不符合“下单/浏览双开关 + 测试按钮 + 独立子页面”的需求。
- 当前设置页没有微信快捷登录绑定入口，也没有员工管理入口。
- `miniprogram/src/pages.json` 里尚未注册声音管理页或员工管理页。

### 3. 登录与声音提醒已有基础，但与最新业务口径不一致

- `miniprogram/src/stores/auth.ts` 当前登录成功和恢复登录态后都会连接商家 WebSocket。
- 当前只识别 `order_notify` 事件，且播放资源是 `/static/sounds/order.wav`。
- `server/internal/handlers/ws/events.go` 已新增 `BroadcastOrderNotify` 与 `BroadcastStoreVisitNotify`，说明后端广播骨架已具备。
- `server/internal/handlers/user/handler.go` 的 `GetStoreHome` 仍在商家 `status != 1` 时直接拒绝访问，这与“休息中允许浏览并推送浏览提醒”冲突。

### 4. 账号安全与微信快捷登录后端已起步，但前端未接线，路由也未完全挂齐

- `server/internal/handlers/merchant/account.go` 已新增：
  - `ChangePassword`
  - `BindWechat`
  - `UnbindWechat`
  - `WechatQuickLogin`
- `server/cmd/server/main.go` 已挂载修改密码与微信绑定/解绑接口，以及 `POST /api/v1/auth/merchant/wechat-login`。
- `miniprogram/src/pages/auth/login.vue` 仍只有账号密码登录，没有快捷登录按钮。
- `miniprogram/src/api/index.ts` 和 `miniprogram/src/types/index.ts` 尚未补齐修改密码、微信绑定、微信快捷登录相关定义。

### 5. 员工管理后端已有 CRUD 基础，但首版方案需要前端承接与权限收口

- `server/internal/handlers/merchant/staff.go` 已支持列表、新增、编辑、删除、重置密码。
- `server/cmd/server/main.go` 当前只挂了员工列表/新增/编辑/删除，尚未挂员工重置密码路由。
- 当前后端没有细粒度权限系统；结合产品决策，首版应采用“仅店主可管理”的轻量收口方案。
- `miniprogram/src/types/index.ts` 中 `MerchantStaff` 字段过少，无法承接提醒设置、微信绑定时间、最近微信登录时间等展示。

### 6. 数据看板页面存在字段错位，埋点链路只完成了访问

- `miniprogram/src/pages/merchant/analytics/index.vue` 依赖字段如 `overview.total_sales`、`item.sales`、`item.sales_count`、`item.sales_amount`。
- `miniprogram/src/api/index.ts` 已封装看板接口，但需要和后端真实返回字段重新对齐。
- `miniprogram/src/utils/analytics.ts` 里只有 `trackVisit` 真正请求后端；`trackPageView`、`trackAddToCart`、`trackCheckout`、`trackPayment` 仍是日志占位。
- `server/internal/models/models.go`、`server/pkg/database/mysql.go`、`server/migrations/20240101000000_full_init.sql` 已开始落地 `user_behavior_events`，说明后端支持继续补最小埋点闭环。

### 7. 已有数据结构变更需要纳入本轮正式方案

- `merchant_staffs` 已新增或正在补齐：
  - `browse_notify_enabled`
  - `wechat_bound_at`
  - `last_wechat_login_at`
- `merchant_staffs.openid` 继续复用为商家员工微信快捷登录绑定标识。
- `user_behavior_events` 已作为最小行为事件表开始落地，适合承接访问、页面浏览、商品浏览、提交订单、支付成功等行为。

## Proposed Changes

### 1. 配送设置与下单链路校正

#### 目标文件

- `miniprogram/src/pages/merchant/delivery-settings.vue`
- `miniprogram/src/pages/store/confirm.vue`
- `miniprogram/src/api/index.ts`
- `miniprogram/src/types/index.ts`
- `server/internal/handlers/merchant/handler.go`
- `server/internal/handlers/user/handler.go`
- `PRD.md`

#### 实现方案

1. 在 `delivery-settings.vue` 增加前端校验函数，保存前统一校验：
   - 基础配送费、免配送门槛、最大配送距离不能为负数。
   - 每条规则必须满足 `min_distance >= 0`、`max_distance > min_distance`、`fee >= 0`。
   - 所有规则按起始距离排序，且不允许重叠。
   - 最后一段规则的 `max_distance` 不能超过 `max_distance`。
2. 在 `server/internal/handlers/merchant/handler.go` 中补同口径后端校验，前端绕过时也会返回明确错误。
3. 统一前端说明文案，把“配送距离”描述为“商家支持的配送范围档位”，避免用户误解为地图定位。
4. `confirm.vue` 改为直接消费 `distance_rules` 生成可选档位，不再按 `0.5km` 固定生成。
5. `confirm.vue` 的配送费展示改为根据商家接口返回规则实时计算，前端不再写死 `0/3/6/10`。
6. 选择超出支持范围的档位时，仅做前端提示和下单前拦截，不接入地图、不做真实定位。
7. `CreateOrder` 中补充两类边界：
   - 商家休息时直接拒绝新的创建订单请求。
   - 已经创建的订单和后续支付流程不因营业状态变化而失效。
8. `PRD.md` 更新“配送距离档位选择”“休息中禁止新下单”“不接第三方地图”的说明与验收项。

#### 决策说明

- C 端距离选择继续沿用简单选择器交互，不新增地图页，降低实现复杂度和出错面。

#### 实现方案

1. `auth.ts` 重构为统一的通知中心：

   - 恢复登录态自动重连。
   - 仅在主动退出登录时断开。
2. 在 `auth.ts` 内新增两套本地音频上下文：
   - 下单提醒音：`/static/sounds/order.mp3`
   - 浏览提醒音：`/static/sounds/browse.mp3`
3. `auth.ts` 识别两种事件：
   - `order_notify`
   - `store_visit_notify`
4. 本地播放规则和在线规则解耦：
   - WebSocket 在线状态仅与登录态相关。

6. `settings.vue` 中将原先“订单提示音”单行开关改成“声音提醒管理”入口，展示当前两个开关的组合状态。
7. `GetStoreHome` 允许休息中的商家店铺继续打开，并返回当前营业状态用于前端展示“休息中，暂不接单”。
8. `RecordUserVisit` 在记录访问成功后，补写 `user_behavior_events` 中的访问事件，并调用 `BroadcastStoreVisitNotify`，保证扫码浏览也能推送提醒。
9. `ws/dev.go` 补浏览提醒测试推送接口，方便联调两种音频。
10. `PRD.md` 更新“登录即在线”“休息中仍收到浏览提醒”“双提醒音管理”的业务口径。

#### 决策说明

- 商家休息后仍然在线，是为了保留“用户浏览提醒”和在线感知能力；真正的业务限制放在创建订单接口上。

## Assumptions & Decisions

### 已锁定决策

1. 不做优惠券与营销配置。
2. 商家登录即在线，在线状态与营业状态解耦。
3. 休息中允许浏览并推送浏览提醒，但禁止创建新订单。
4. 已创建订单和支付流程不因商家休息而失败。
5. 声音提醒拆成下单提醒与浏览提醒两个员工维度开关。
6. 修改密码成功后立即退出并重新登录。
7. 微信快捷登录绑定在员工维度上实现。
8. 员工管理首版仅 `owner` 可管理。
9. 配送距离采用商家自定义档位，不做真实定位。

### 本轮不纳入范围

1. 服务商端看板重构。
2. 优惠券、分享券、营销活动。
3. 员工细粒度权限配置。
4. 第三方地图与真实距离计算。
5. 高级漏斗、留存、分群分析。

## Verification Steps

### 1. 配送链路

1. 商家配送设置可正确加载、编辑、保存。
2. 非法距离区间、重叠区间、超出最大距离会被前后端一致拦截。
3. C 端确认页距离选项来自商家真实配置，不再写死生成。
4. 休息中的商家无法创建新订单。
5. 已创建订单在支付时，商家切到休息不影响支付成功与成功提示。

### 2. 在线与声音提醒

1. 商家登录后即连接 WebSocket，退出登录后断开。
2. 商家切换休息后，WebSocket 不断开。
