# 用户下单页配送地址选择与地址管理计划

## Summary
- 目标：在用户下单确认页支持配送地址选择，而不是仅手填；支持从微信快速导入地址、从用户地址簿选择历史地址，并提供地址管理入口。
- 范围：优先复用现有 `user_addresses` 地址簿能力，不新增“从订单聚合历史地址”的独立数据层；微信导入地址后自动写入地址簿；地址管理入口先仅放在下单页。
- 交付结果：
  - `pages/store/confirm` 可查看当前选中地址、进入地址列表、进入地址编辑、微信导入地址
  - 新增用户侧地址列表页和地址编辑页
  - 下单页默认回填默认地址或最近一次用户选中的地址
  - 继续使用现有创建订单接口提交 `delivery_address/contact_name/contact_phone`

## Current State Analysis
- 当前确认页 `miniprogram/src/pages/store/confirm.vue` 在配送模式下仍然是纯手填：
  - `deliveryAddress`
  - `contactName`
  - `contactPhone`
  - `deliveryDistance`
- 当前确认页已经具备配送/堂食/自提切换与配送规则加载逻辑，可直接在 `deliveryType === 1` 的区域接入地址选择，不需要重做下单主流程：
  - 文件：`miniprogram/src/pages/store/confirm.vue`
- 小程序前端 API 已封装用户地址 CRUD：
  - `getUserAddresses()`
  - `createUserAddress()`
  - `updateUserAddress()`
  - `deleteUserAddress()`
  - 文件：`miniprogram/src/api/index.ts`
- 前端类型中已有 `UserAddress`：
  - 字段：`id/name/phone/province/city/district/address/lat/lng/is_default`
  - 文件：`miniprogram/src/types/index.ts`
- 后端已实现用户地址簿 CRUD，且支持默认地址语义：
  - 路由：`GET/POST/PUT/DELETE /api/v1/user/addresses*`
  - 文件：`server/internal/handlers/user/addresses.go`
- 小程序 `manifest.json` 已声明 `chooseAddress` 权限，但当前代码里没有实际接入微信地址导入。
- 当前 `pages/store` 下未注册独立地址页，`pages.json` 中也没有地址相关页面。

## Assumptions & Decisions
- 历史地址来源以现有地址簿 `user_addresses` 为准，不在本次计划中新增“从历史订单去重聚合最近地址”能力。
- 微信快速导入地址后，默认自动保存到地址簿，并同步设为当前下单地址。
- 地址管理入口先只在 `pages/store/confirm` 中提供；不扩展到“我的订单”或其它用户常驻页面。
- 订单创建接口保持现状，不新增 `address_id`；确认页在选中地址后，把地址内容映射到现有订单入参：
  - `delivery_address`
  - `contact_name`
  - `contact_phone`
- 地址簿详情接口不是必需项，本次地址编辑可以通过地址列表页携带对象或通过列表再拉取一次数据实现。
- 最小实现优先，不新增“地址标签”“门牌号拆分”“地图选点”“最近使用时间”等增强字段。

## Proposed Changes

### 1. 改造确认页地址区为“地址卡片 + 选择入口”
- 修改文件：
  - `miniprogram/src/pages/store/confirm.vue`
- 变更内容：
  - 将配送模式下原有三段手填输入改为“当前地址卡片 + 选择地址/新增地址/微信导入”的交互
  - 在已有 `deliveryType === 1` 条件块中：
    - 展示当前选中的收货人、联系电话、完整地址
    - 无地址时展示空态提示和“去选择地址”按钮
    - 保留配送距离选择器与备注输入
  - 增加页面状态：
    - `selectedAddress`
    - `addressList`
    - `loadingAddresses`
  - 增加页面逻辑：
    - `loadAddresses()`
    - `selectAddress()`
    - `goAddressList()`
    - `importWechatAddress()`
    - `applySelectedAddress()`
  - 下单提交时：
    - 从 `selectedAddress` 映射 `delivery_address/contact_name/contact_phone`
    - 若配送模式下没有地址，则不允许提交
- 为什么这样做：
  - 最大限度复用当前下单流程
  - 变更集中在地址输入方式，不影响配送规则、购物车、支付链路

### 2. 新增地址列表页
- 新增文件：
  - `miniprogram/src/pages/store/address-list.vue`
- 修改文件：
  - `miniprogram/src/pages.json`
- 页面职责：
  - 拉取并展示用户地址簿
  - 支持：
    - 选择当前地址并返回确认页
    - 新增地址
    - 编辑地址
    - 删除地址
    - 设置默认地址（优先通过现有更新接口写 `is_default=true`）
    - 微信导入地址
- 路由建议：
  - `pages/store/address-list`
- 页面交互建议：
  - 列表项点击：选择当前地址并返回
  - 列表项操作：编辑 / 删除 / 设为默认
  - 页面底部按钮：新增地址、微信导入
- 为什么单独做列表页：
  - 复用性高，后续若需要在用户侧常驻入口开放地址管理，可直接复用

### 3. 新增地址编辑页
- 新增文件：
  - `miniprogram/src/pages/store/address-edit.vue`
- 修改文件：
  - `miniprogram/src/pages.json`
- 页面职责：
  - 新增地址
  - 编辑已有地址
- 表单字段：
  - 联系人
  - 联系电话
  - 省/市/区
  - 详细地址
  - 是否默认地址
- 页面逻辑：
  - 新增模式：调用 `createUserAddress`
  - 编辑模式：调用 `updateUserAddress`
  - 保存成功后返回地址列表页，并触发列表刷新
- 为什么需要编辑页而不是弹窗：
  - 小程序表单内容较多，独立页面更稳定，也与现有项目页面交互风格一致

### 4. 接入微信地址导入
- 修改文件：
  - `miniprogram/src/pages/store/confirm.vue`
  - `miniprogram/src/pages/store/address-list.vue`
  - 可能补一个工具文件：`miniprogram/src/utils/address.ts`
- 变更内容：
  - 使用小程序地址导入能力（与 `manifest.json` 已声明的 `chooseAddress` 权限对应）
  - 将微信返回字段映射为现有 `UserAddress` 入参：
    - `userName -> name`
    - `telNumber -> phone`
    - `provinceName/cityName/countyName -> province/city/district`
    - `detailInfo -> address`
  - 导入后直接调用 `createUserAddress`
  - 默认策略：
    - 若地址簿为空，可设为默认地址
    - 导入成功后立即设为当前选中地址
- 兼容策略：
  - 若用户取消微信选择，静默结束，不报错
  - 若导入失败，提示失败原因

### 5. 地址回填与状态同步
- 修改文件：
  - `miniprogram/src/pages/store/confirm.vue`
  - 可能补充一个轻量工具或页面参数约定
- 变更内容：
  - 进入确认页或返回确认页时自动刷新地址列表
  - 优先选择规则：
    1. 当前页面已选中的地址
    2. 地址簿中的默认地址
    3. 地址簿中的第一条地址
  - 从地址列表返回确认页时，通过页面参数或本地缓存/事件方式传回选中地址 ID
  - 确认页再基于地址 ID 从地址列表中恢复选中项
- 为什么要统一回填规则：
  - 保证下单页、地址列表页、地址编辑页之间状态简单一致，避免出现“已选地址丢失”

### 6. 可选但建议同步的订单展示补强
- 修改文件：
  - `miniprogram/src/pages/store/order-detail.vue`
- 变更内容：
  - 在配送订单详情中展示：
    - 收货地址
    - 联系人
    - 联系电话
- 说明：
  - 这不是用户请求的核心功能，但基于仓库现状，订单详情已有地址数据却前端未展示，和本次“地址管理”用户心智强相关
  - 若要严格控范围，也可在实施时作为次要项，不影响主链路交付

- `miniprogram/src/pages/store/confirm.vue`
  - 重构配送表单区为地址卡片交互
  - 接入地址列表加载、地址选择、微信导入
  - 调整提交时的地址映射
- `miniprogram/src/pages/store/address-list.vue`
  - 新增地址管理列表页
- `miniprogram/src/pages/store/address-edit.vue`
  - 新增地址编辑页
- `miniprogram/src/pages.json`
  - 注册两个新页面
- `miniprogram/src/api/index.ts`
  - 复用现有地址 CRUD；如需，可补充 `setDefault` 辅助封装，但底层仍走 `updateUserAddress`
- `miniprogram/src/types/index.ts`
  - 视实现补充地址页面需要的类型辅助定义

  - 放地址格式化、微信地址映射等轻量工具
- `miniprogram/src/pages/store/order-detail.vue`（可选增强）
  - 展示配送地址信息

## Implementation Steps
1. 在 `pages/store/confirm.vue` 中梳理当前配送表单区状态，替换为地址卡片和地址选择入口。
2. 新增 `pages/store/address-list.vue`，接入 `getUserAddresses/createUserAddress/updateUserAddress/deleteUserAddress`。
3. 新增 `pages/store/address-edit.vue`，完成新增与编辑地址表单。
4. 在地址列表页与确认页接入微信导入地址，并自动写入地址簿。
5. 打通确认页与地址列表页之间的返回和选中状态同步。
6. 视范围决定是否在 `order-detail.vue` 中补显示配送地址信息。
7. 更新 `pages.json` 并完成页面间跳转串联。

## Verification Steps
- 页面与交互：
  - 配送模式下，确认页可进入地址列表页
  - 地址列表页可新增、编辑、删除、设默认、选择地址
  - 微信导入地址后自动保存到地址簿，并回填到确认页
  - 配送模式下，未选择地址不能提交订单
  - 堂食/自提模式下，不展示地址卡片，不受地址必填限制
- 数据与回填：
  - 默认地址进入确认页可自动回填
  - 新增地址后返回确认页可立即作为当前地址使用
  - 切换地址后，下单提交到后端的 `delivery_address/contact_name/contact_phone` 与所选地址一致
- 构建与诊断：
  - `miniprogram` 执行 `npm run build:mp-weixin`
  - 对新建与改动页面执行诊断，确保无新增错误

## Out Of Scope
- 从历史订单中独立聚合“最近地址”
- 新增地址标签（家/公司/学校）
- 新增地图选点、逆地理编码、门牌号高级字段
- 为订单创建接口增加 `address_id`
- 在用户常驻页面新增“地址管理”入口
