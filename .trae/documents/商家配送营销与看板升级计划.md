# 商家配送看板与在线能力升级计划

## Summary

目标：围绕商家端补齐配送、数据看板、在线状态、账号安全、员工管理等能力，并把对应实现同步更新到 `PRD.md`，保证代码、接口和产品文档一致。

本次计划按以下已锁定范围推进：

1. 配送设置按“全链路校正”处理，不只修页面，还要校验规则合法性并确认用户下单时真实生效。
2. 数据看板优先完善商家端，基于现有订单统计与用户埋点补齐真实可展示指标。
3. WebSocket 在线状态调整为“商家登录即在线”：只要商家已登录就保持连接；即使点击休息，仍可接收“顾客正在浏览”提醒；休息状态只阻止新下单，不影响已进入支付流程的订单完成支付。
4. 声音提醒拆分为独立子页面，分别管理“用户下单提醒”“用户浏览提醒”，并提供测试播放按钮。
5. 配送距离不接入第三方地图，改为用户下单时从商家配置的距离档位中手动选择；超出范围仅提示，不做真实定位计算。
6. 商家端设置页增加“修改密码”弹窗，并支持当前员工绑定微信后使用快捷登录。
7. 员工管理采用轻量方案：列表、新增、编辑角色/状态、删除、重置密码；不引入复杂权限系统。
8. 所有本次改动涉及的产品说明、接口、数据结构、验收项均同步更新到 `PRD.md`。

## Current State Analysis

### 1. 配送设置并非完全未对接，但仍缺少“真闭环”

已确认：

1. 前端页面 `miniprogram/src/pages/merchant/delivery-settings.vue` 已调用 `getDeliverySettings()` / `updateDeliverySettings()`。
2. 后端路由 `GET/PUT /api/v1/merchant/delivery-settings` 已在 `server/cmd/server/main.go` 挂载。
3. 后端 `server/internal/handlers/merchant/handler.go` 已支持读取和保存 `enabled / base_fee / free_delivery_amount / max_distance / distance_rules`。
4. C 端确认页 `miniprogram/src/pages/store/confirm.vue` 已提交 `delivery_distance`，后端 `server/internal/handlers/user/handler.go` 已按该值计算配送费。

当前缺口：

1. 页面仍像“基础表单页”，没有对距离区间、空值、重叠、顺序、最大距离一致性做前端校验。
2. 后端保存时也未见明确的规则合法性校验，错误语义较弱。
3. 当前交互仍容易让人理解成“定位距离”或“写死距离”，需要明确改成商家自定义档位 + 用户手选，不接第三方地图。
4. 用户选择超出商家配置距离时，需要稳定提示而不是进入复杂定位流程。

结论：本轮不做营销配置与优惠券，重点补齐设置页内真正可操作的账号安全、声音管理、微信快捷登录与组织管理能力。

## Proposed Changes

### 1. 配送设置全链路校正

#### 目标文件

- `miniprogram/src/pages/merchant/delivery-settings.vue`
- `miniprogram/src/pages/store/confirm.vue`
- `miniprogram/src/api/index.ts`
- `miniprogram/src/types/index.ts`
- `server/internal/handlers/merchant/handler.go`
- `server/internal/handlers/user/handler.go`
- `PRD.md`

#### 具体变更

1. 前端配送设置页补规则编辑校验：
   - 距离区间必须为正数或 0
   - `min_distance < max_distance`
   - 规则按区间顺序排列
   - 规则不能重叠
   - 规则末段不能超过 `max_distance`
   - 空规则、非法输入给出明确提示
2. 后端 `UpdateDeliverySettings` 增加同口径校验，避免前端绕过提交脏数据。
3. 明确 `distance_rules` 为空数组时表示“清空按距离收费规则”。
4. C 端确认页改为“手动选择距离档位”而非地图定位：
   - 距离选项来自商家配置的 `distance_rules`
   - 用户从下拉或选择器中手动选择
   - 不接入第三方地图组件
   - 若选择超出商家支持范围，前端直接提示
5. 复核 `CreateOrder` 的配送费计算逻辑，确保：
   - 按配置命中距离区间
   - 满免金额优先级正确
   - 超出配送范围返回稳定错误
   - 商家停业时无法下单
6. PRD 补充“配送距离为商家自定义档位选择，不做真实定位计算”的说明和验收项。

#### 原因

- 用户感知到“写死”，本质上是链路可信度不足；必须把前端编辑、后端存储、用户下单三段一起校正。

## Assumptions & Decisions

### 已锁定决策

1. 配送设置按“全链路校正”处理，不仅修页面。
2. 本轮取消商家发优惠券与营销配置改动。
3. 数据看板优先完善商家端，不在本轮同时扩展服务商端。
4. 在线状态改为“登录即在线”，不再跟随营业状态断开。
5. 声音提醒拆为“下单提醒”和“浏览提醒”两个员工维度开关，由独立子页面管理。
6. 配送距离不做真实定位，只做商家配置档位 + 用户手动选择。
7. 员工管理采用轻量方案，不做复杂权限体系。
8. 修改密码面向当前登录商家员工账号，以弹窗方式实现。
9. 微信快捷登录基于当前员工绑定微信 `openid` 实现。
10. 所有实现改动同步到 `PRD.md`。

### 设计约束

1. 优先复用当前已有后端路由、模型和页面骨架，避免无必要重构。
2. 埋点系统只补“看板必须的最小闭环”，不扩展成完整分析平台。
3. WebSocket 在线状态与营业状态解耦；商家休息时仍保持在线并接收浏览提醒，但只拦截新的创建订单请求。
4. 已创建并进入支付流程的订单，不因商家中途切换休息而支付失败。

### 暂不纳入本次范围

1. 服务商端数据看板重做
2. 优惠券与营销配置
3. 多券型并存
4. 员工细粒度权限控制
5. 复杂营销活动编排
6. 完整漏斗、留存、分群等高级分析能力
7. 第三方地图与真实距离测算

## Verification Steps

### 1. 配送设置

1. 商家端可正确加载已有配送设置。

5. 选择超出范围时有明确提示，不接入地图组件。
6. C 端创建配送订单时，配送费按规则真实命中。

### 2. 数据看板

1. 商家看板页面不再出现字段错位或空白展示。

3. 访问埋点、下单、支付成功等基础事件能够反映到看板指标。

### 3. 在线状态与提示音

1. 商家登录后自动建立 WebSocket，休息中登录也保持在线。

4. 用户进入商家主页后，商家可收到 `store_visit_notify` 并播放“浏览提醒” mp3。
5. 已创建且正在支付的订单，在商家中途切换休息后仍可支付成功，用户会看到下单成功提示。
6. 营业中收到 `order_notify` 时播放“下单提醒” mp3。
7. 声音提醒子页面可分别开关两类提醒，并可测试播放。

2. 原密码错误、两次新密码不一致、弱密码等场景有明确提示。
3. 当前员工可绑定微信快捷登录，登录页显示微信快捷登录按钮。
4. 未绑定商家账号的微信快捷登录会提示“您还不是商家，请注册后使用”。
5. 员工列表、新增、编辑、删除、重置密码可用。
6. 不允许跨商家或越权操作员工数据。
