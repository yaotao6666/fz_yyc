# 健康档案多成员管理与首页健康宣教优化 — 实施方案

## 1. 概述（Summary）

对用户端小程序「我的健康」进行两项改造：

1. **健康档案多成员管理**：同一账号可管理多个健康档案（**最多 5 个**），用于「本人 / 父母 / 其他亲属」分别建档、自助评估、查看各自评估记录。
2. **健康宣教迁移**：将「健康宣教」入口从「我的健康」中移除，改到**首页**（store/home）新增一个类似轮播图高度的板块展示已发布宣教文章。

> 说明：后端多档案的数据模型与基础 CRUD（`relation` 字段、`record_id`、多档案列表/增删改接口）在阶段五 8.2 已完成，本次主要补齐「最多 5 个」的上限校验、评估记录按档案过滤，以及前端多成员交互与宣教首页板块。

**C. 评估记录按档案过滤** — [assessment.go](file:///Users/yaotao/Documents/trae_projects/fz_yyc_cxsm/server/internal/handlers/health/assessment.go)

改造 `UserListAssessments`，支持可选 `record_id` 查询参数：

```go
func UserListAssessments(c *gin.Context) {
    userID := middleware.GetUserID(c)
    page, _ := strconv.Atoi(c.DefaultQuery("page", "1"))
    pageSize, _ := strconv.Atoi(c.DefaultQuery("page_size", "10"))
    if page < 1 { page = 1 }
    if pageSize < 1 || pageSize > 100 { pageSize = 10 }

    query := database.DB.Model(&models.HealthAssessment{}).Where("user_id = ?", userID)
    if recordIDStr := c.Query("record_id"); recordIDStr != "" {
        if rid, err := strconv.ParseUint(recordIDStr, 10, 64); err == nil && rid > 0 {
            query = query.Where("record_id = ?", rid)
        }
    }

    var total int64
    query.Count(&total)

    var list []models.HealthAssessment
    query.Preload("Form").
        Order("created_at DESC").
        Offset((page - 1) * pageSize).
        Limit(pageSize).
        Find(&list)

    response.Success(c, gin.H{ "list": list, "total": total })
}
```

## 4. 假设与决策（Assumptions & Decisions）

- **上限常量** 5 个仅作用于前端「＋添加成员」显隐与后端 `UserCreateHealthRecord`；存量单档案兼容接口 `UserUpsertHealthRecord`（下单页回退）不受限。
- **编辑页按 id 预填** 通过 `listUserHealthRecords()` 查找，不新增后端「按 id 查询单档案」接口（最多 5 条，代价极低）。
- **适配建议** 为账号级（非档案级），保留在「我的健康」操作宫格中，不与成员绑定。
- **首页宣教板块** 采用横向滚动的文章标题卡片（高约 280-300rpx，对齐轮播图高度），点击进详情、右上「更多」进宣教列表；不使用封面图（文章可能存在无封面情况）。
- **无新增数据库迁移**：`relation` 与 `record_id` 字段均已存在，本次仅为代码逻辑与前端交互改造。
- **评估记录默认语义**：未传 `record_id` 时仍返回账号全部评估记录（向后兼容）；前端统一按当前成员传 `record_id`。
