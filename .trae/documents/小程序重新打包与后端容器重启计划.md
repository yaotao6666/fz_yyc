# 小程序重新打包与后端容器重启计划

## Summary

本次任务目标是完成两件事：

1. 重新打包微信小程序产物。
2. 重新构建后端 Docker 镜像并启动容器，确认服务恢复正常。

本次不涉及代码改动、配置改动、数据库结构调整或业务逻辑变更，仅执行构建、镜像重建与服务启动。

## Current State Analysis

### 小程序构建入口

- `miniprogram/package.json` 已定义微信小程序构建脚本：`npm run build:mp-weixin`。
- 小程序生产构建输出目录为 `miniprogram/dist/build/mp-weixin`。
- 仓库内已有 `.trae/skills/miniprogram-build.md`，其中也明确了构建命令与输出目录。

### 后端容器启动方式

- 后端容器编排文件为 `server/docker-compose.yml`。
- Compose 中实际服务名为：
  - `mysql`
  - `redis`
  - `api`
- `server/README.md` 已明确：
  - 重启单个 API 服务可用 `docker compose restart api`
  - 如需重新构建并启动可用 `docker compose up --build -d`
- `server/Dockerfile` 已定义 Go 多阶段构建流程，可直接用于重建 `api` 镜像。

### 当前任务边界

- 用户需求已更新为“重新打包 + 重新构建 Docker 镜像”。
- 因此执行顺序调整为：
  - 小程序重新执行构建
  - 后端直接重建并启动 `api` 服务镜像
- 本次不再优先走单纯 `docker compose restart api`。

## Proposed Changes

### 1. 小程序重新打包

#### 目标目录

- `miniprogram/`

#### 执行方式

1. 进入 `miniprogram` 目录。
2. 运行 `npm run build:mp-weixin`。
3. 检查产物目录 `miniprogram/dist/build/mp-weixin` 是否生成且时间戳更新。

#### 说明

- 若构建失败，先查看报错并停止后续步骤，不直接进入容器重启。
- 默认不删除 `node_modules` 或 `dist`，除非构建失败且错误明确指向缓存或依赖异常。

### 2. 后端镜像重建与容器启动

#### 目标目录

- `server/`

#### 执行方式

1. 进入 `server` 目录。
2. 执行 `docker compose up --build -d api`，重新构建并启动后端 API 服务。
3. 执行 `docker compose ps` 检查 `api`、`mysql`、`redis` 状态。
4. 执行 `docker compose logs --tail 50 api` 检查最近启动日志。

#### 说明

- 本次需求已明确为“重新构建 Docker 镜像”，因此直接重建 `api` 服务镜像。
- 默认不重建 `mysql`、`redis`，避免扩大影响范围。
- 不执行 `docker compose down -v` 等会影响数据卷的操作。

### 3. 结果确认

#### 核对内容

1. 小程序构建成功结束，无编译错误。
2. `miniprogram/dist/build/mp-weixin` 为最新构建产物。
3. `docker compose ps` 中 `api` 处于运行状态。
4. `docker compose logs --tail 50 api` 无明显启动报错。
5. 如镜像构建失败，保留构建日志并停止继续操作。

## Assumptions & Decisions
